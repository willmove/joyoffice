# T301 格式与表格结构修订

任务原文：

> 自动验证：格式拒绝还原、表格结构与内容守恒、局部接受合法性测试。

> 人工验收：对含表格的合同增删行、改样式并交换审阅。

> 产物：属性前值、段落标记、编号、节属性和表格网格结构修订，覆盖支持的 story。

> 错误路径：非法嵌套、修订依赖冲突和丢失原始状态不得猜测恢复。

状态是 `in_progress`（2026-10-22 由 `planned` 改来）。第一切片只做正文段落（`w:tbl` 之外）的 `w:pPrChange`（ECMA-376 §17.13.5.29）与 `w:rPrChange`（§17.13.5.30）。2026-10-26 第二切片把表格属性修订 `w:tblPrChange`／`w:trPrChange`／`w:tcPrChange`（§17.13.5）类型化到表、行、单元格上，可按 id 接受／拒绝、批量解决并一步撤销；结构修订 `w:cellIns`／`w:cellDel`／`w:cellMerge`、`w:tblGridChange`、`w:tblPrExChange`，以及段落标记、编号、节属性修订仍未实现。本清单全部是自动证据，人工验收一条都没有做，不把任务标成完成。实现记录见 [IMPLEMENTATION](../IMPLEMENTATION.md)，任务证据见 [TASKS](../TASKS.md)。

## GUI 抽查脚本

本切片未执行下列图形界面步骤，不作为通过记录。仓库里没有带 `w:pPrChange`／`w:rPrChange` 的样例文件：[DOCX-FEAT-T300-REVIEW.docx](../../../tests/fixtures/feature/DOCX-FEAT-T300-REVIEW.docx) 只含 `w:ins`／`w:del`，也没有表格，所以第 1 步要自己造样例。

1. 在 Word 或 WPS 里打开一份含表格的合同，开「跟踪修订」，改一处正文段落的对齐与一处文字的粗体／斜体，改表格的对齐方式或某一行的「允许跨页断行」，再在表格里增删一行，另存为样例。
2. 用 JoyWord 打开该样例。正文的两处格式变更应带作者与日期出现在审阅信息里；表格属性变更（对齐、跨页断行）应能在光标落入该表时被报告为当前修订；增删行那张表应让整篇只读，正文也不能编辑。
3. 只保留正文格式变更的那份样例里，逐项「拒绝」一处：格式应回到变更前的值，页边标记消失；一次撤销应把记录和格式一起恢复。
4. 「接受」另一处：格式保持变更后的值，记录消失。再「全部接受」，一次撤销恢复整篇。
5. 另存为新文件，用 Word 或 WPS 打开：已解决的段落不应再带 `w:pPrChange`／`w:rPrChange`，未解决的段落必须原样带着记录，且 Word 里的修订列表与 JoyWord 一致。
6. 对未决格式修订的段落改样式、改编号或在其间插入文字，JoyWord 应显式拒绝导出并说明原因，而不是产出一个抹掉记录的 docx。
7. 本清单在第 5 步没有本机记录之前，不关闭人工验收。
