# T104 撤销、本地日志与恢复

任务原文：

> 自动验证：故障注入、有效前缀恢复、保存版本竞争、undo／redo 属性测试。

> 人工验收：强制结束测试进程后恢复，比较最后完整事务和正式保存文件。

> 产物：独立撤销栈、日志校验、周期快照、dirty 版本与恢复选择。周期快照必须包含 PackageBacking 与原包基线所需信息，不能只含模型；加密文档不落明文副本；快照写入经临时文件、校验与原子改名，并保留上一代有效副本。

> 错误路径：磁盘满、截断、外部修改、保存期间继续编辑和日志迁移失败不丢原件。

2026-11-01 状态为 `done`。原任务的实现、故障注入／竞争自动验证、强制结束真实进程后恢复与正式源件对照均已完成，见 [本轮报告](../../joyoffice/validation/20261101-t104/README.md)。V3 检查点保存原包基线、当前已验证 DOCX、完整正文及版本，恢复所有已可导出的编辑语义。V1／V2 保持只读兼容及显式文本恢复路径；新生产检查点不降级为文本。

物理断电、存储设备掉电持久性与跨平台认证仍未实测，继续作为 T702／T700 专项；这不是本轮进程终止或注入 IO 错误的通过记录。T104 原准则要求可注入故障存储适配、有效前缀、并发与真实进程强制结束，未把这些设备专项改记为已验证。

## GUI 抽查脚本

2026-10-30 Windows 已执行强制结束、恢复和落盘比较、明确丢弃后重启；结果与边界见 [本机 GUI 记录](../verification/m7-gui-20261030.md)。下列脚本仍可用于其他平台补验。

1. 打开一份文档，做一次修改但不保存，记下正文最后一句。
2. 用任务管理器强制结束 JoyWord 进程。
3. 重新启动 JoyWord 并打开同一份文档：应提示恢复到强制结束前的状态，正文最后一句应是修改后的内容。
4. 与正式保存的文件对照：正式保存的那份不含未保存的修改，恢复出来的那份含。两者不应互相覆盖。
5. 在恢复对话框上选择丢弃：再次打开该文档应是上次正式保存的内容，而不是丢弃后的空文档。
6. 本清单在第 3 步没有本机记录之前，不关闭人工验收。

2026-10-30 新增回归：`text_recovery_preserves_unchanged_runs_and_exports_after_unicode_edits`、`repeated_recovery_never_overwrites_an_existing_or_locked_recovery_copy`，见 [恢复测试](../../../crates/joyword-shell/tests/recovery_formatted_text.rs)。Windows 真窗口发现并复验两个恢复缺陷，详见本轮 GUI 记录。
