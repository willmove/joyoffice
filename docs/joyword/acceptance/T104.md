# T104 撤销、本地日志与恢复

任务原文：

> 自动验证：故障注入、有效前缀恢复、保存版本竞争、undo／redo 属性测试。

> 人工验收：强制结束测试进程后恢复，比较最后完整事务和正式保存文件。

> 产物：独立撤销栈、日志校验、周期快照、dirty 版本与恢复选择。周期快照必须包含 PackageBacking 与原包基线所需信息，不能只含模型；加密文档不落明文副本；快照写入经临时文件、校验与原子改名，并保留上一代有效副本。

> 错误路径：磁盘满、截断、外部修改、保存期间继续编辑和日志迁移失败不丢原件。

状态是 `in_progress`（2026-10-23 由 `planned` 改来）。2026-10-23 的生产恢复双代切片（[#90](https://github.com/willmove/joyoffice/pull/90)）覆盖：两个发布槽交替写入、代次与 CRC 校验、损坏回退、旧格式只读兼容和保存期间的编辑竞争。2026-10-26 切片补上独立撤销栈、日志校验与 undo／redo 属性测试（下表三行 `automated`）。周期快照仍是保存时检查点，不是周期快照。人工验收一条都没有做，不把任务标成完成。实现记录见 [IMPLEMENTATION](../IMPLEMENTATION.md)，任务证据见 [TASKS](../TASKS.md)。

## GUI 抽查脚本

本切片未执行下列图形界面步骤，不作为通过记录。

1. 打开一份文档，做一次修改但不保存，记下正文最后一句。
2. 用任务管理器强制结束 JoyWord 进程。
3. 重新启动 JoyWord 并打开同一份文档：应提示恢复到强制结束前的状态，正文最后一句应是修改后的内容。
4. 与正式保存的文件对照：正式保存的那份不含未保存的修改，恢复出来的那份含。两者不应互相覆盖。
5. 在恢复对话框上选择丢弃：再次打开该文档应是上次正式保存的内容，而不是丢弃后的空文档。
6. 本清单在第 3 步没有本机记录之前，不关闭人工验收。
