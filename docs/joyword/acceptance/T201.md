# T201 验收清单

2026-11-01 状态为 `done`。T201 的基础类型化表格产物、错误路径、自动验证和合同表格 GUI 场景已有证据，见 [UOS 原生验收](../../joyoffice/validation/20261101-t201/README.md)。本轮补齐列边界拖拽、单格纯色底纹设置／清除及 Linux 编辑命令入口，修复表格操作后的正文焦点与空白边距字段写零。

支持范围沿用基础类型化表格：行列增删、规则水平／垂直合并拆分、六种已支持边框、直接 sRGB／auto 底纹、一层嵌套内容读写／绘制及已有表格属性。第二层嵌套保持不透明／拒绝契约；主题底纹、四角条件及完整复杂表格／跨软件几何对照继续开放，见 T200／T500 与本轮剩余任务记录。它们不改记为已实现。

> 自动验证：网格不变量、内容归属、合并逆操作和 DOCX 读写样例。
>
> 人工验收：制作合同表格，插行、合并、拆分、撤销、保存重开。
>
> 产物：真实网格、行列增删、基础合并拆分、边框／底纹及表格内选择。
>
> 错误路径：不规则合并、结构破坏和跨只读对象编辑不能产生非法模型。

## GUI 抽查脚本

2026-11-01 已在 UOS 25 / X11 / RADV 的真实窗口执行基本合同表场景。输入由 X11 合成键鼠注入，截图来自实际窗口，保存件由独立 ZIP／XML 与 Poppler 读回；这不是系统输入法或物理键鼠认证。可复跑入口：`python3 scripts/smoke_word_table_linux.py --output <新的输出目录>`。运行环境、二进制散列、20 次保存及观察记录见 [本轮报告](../../joyoffice/validation/20261101-t201/README.md)。下列扩展的样式／深嵌套拒绝由自动测试覆盖，未另做 GUI。

1. 新建文档，编辑菜单「插入表格」或插入页的表格按钮，做成 3 列合同表：名称、数量、金额。
2. 插入一行、删除一行、向右合并两格、再拆分。每一步撤销应回到上一步的网格，不能留下缺列或孤立的纵向合并。
3. 打开表格属性，改表宽和对齐，取消应不产生撤销步；确认后一次撤销恢复。
4. 保存为新的 docx，退出后重新打开。合并、边框和文字应还在。
5. 若样例带首列底纹，看首列是否盖过纵向条纹。这是 ECMA-376 的层叠顺序，不是 Word 的实现偏差。
6. 把表再嵌一层。第二层应整表保持只读，旁边的段落编辑不得生成一份丢掉该表的包。

## 本轮补充回归

- `cell_fill_and_table_border_apply_together_and_undo_together`：底纹只影响当前单元格，与边框同一次撤销，清除和非法颜色。
- `a_cancelled_table_dialog_does_not_open_a_transaction`：新增原生对话框空白边距字段的回归，保持应用默认边距与版本。
- `resized_grid_and_cell_widths_round_trip_without_losing_shading_or_content`：改写网格、单格宽度并保留原底纹／边框的 DOCX 往返。
- `column_resize_and_cell_fill_refuse_read_only_and_preserved_tables`：只读和未知保留拒绝，版本与历史不变。
