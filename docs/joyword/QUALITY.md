# JoyWord 质量与验收

版本 0.3 · 2026-10-17。数值是初始预算和验收门槛，**不是现有实测成绩**。对应任务见 [TASKS](TASKS.md)，当前证据见 [IMPLEMENTATION](IMPLEMENTATION.md)。

## 1. 五层验证

1. 模型与事务性质测试：结构合法、撤销还原、位置映射、样式解析和审阅投影。
2. 规范样例测试：每个元素／属性／组合有最小原创输入和预期语义。
3. 跨软件往返测试：固定 Word 版本为主；中文文档互操作以固定 WPS 版本并列；LibreOffice 为补充。
4. 布局与交互测试：行页断点、基线、对象位置、选择区、光标与 IME。
5. 故障与安全测试：损坏输入、资源预算、取消、崩溃和并发修改。

截图是辅助证据；不以像素相似率代替语义、关系或几何验证。测试数量和代码覆盖率不能单独作为兼容度。功能覆盖率按证据等级统计（存在／单元测试／语料／参考对照），命令或按钮的注册数量不计入兼容度，空壳与替代实现计为未实现。

## 2. 核心不变量

- 原子事务失败前后，文档语义、版本与撤销栈不变。
- 执行后撤销恢复原语义；版本仍保持单调性。
- 位置映射组合与逐步映射一致；未知锚点不任意落到其他文本。
- Revision 原始／最终投影互不修改持久内容；无标记视图不能删除修订。
- 对可表示的原稿 A 与目标稿 B，比较生成的修订全部拒绝得到 A、全部接受得到 B。
- 导入／导出支持子集语义一致，未知保留部件和关系没有静默丢失。
- 缩放／DPI 不改变文档物理几何，屏幕／PDF／打印使用同一稳定场景。
- AI 关闭后不能新发请求或提交提案；迟到响应不会变脏文档。

对属性测试的随机失败保存最小重现、种子和版本；不能只提高重试次数掩盖不确定性。

## 4. 语料与参考环境

语料清单采用机器可读 case registry，详见 tests/fixtures 的说明。原创文本样例可以早期登记，但在生成文档和参考结果之前必须标 planned，不能算作格式或几何测试已通过。

每个参考结果绑定 case ID、源文件散列、JoyWord 修订、参考软件完整版本、操作系统、字体文件散列、locale、页面／打印设置和操作步骤。记录参考产品的许可证和可访问测试环境，缺少环境时保留待验收状态。Word 参考环境固定为 Word 2024 永久版（功能冻结；企业渠道为 Office LTSC 2024，零售渠道为 Office 家庭版／家庭和商业版 2024，二者同为冻结的 2024 行为内核），观测记录绑定确切 build；Microsoft 365 每月功能更新，不作长期基准。Word 几何参考通过固定版本导出 PDF 并抽取字形坐标获得；黑盒得出的排版规则登记到 [规则目录](layout_rules.md) 并引用样例 ID。

几何验收分两类：相同 JoyWord 场景在屏幕／PDF 的单位转换误差不超过 0.01 pt；相同字体和固定 Word profile 的最小规范样例，行／页断点一致，主要基线与对象位置误差不超过 0.5 pt。复杂组合语料的例外逐样例登记，不能用平均值掩盖整页漂移。

编辑行为登记表把每条行为绑定固定 Word 的观测记录（版本、样例 ID、日期、截图散列）与对应测试名，由检查器校验测试名存在；来自其他实现的观测只作待验证假设，必须在固定的 Word 2024 永久版参考环境复核后才能登记为规则。登记表文件为 [behavior_registry.json](behavior_registry.json)（schema 1：`hypothesis` 条目不携带观测，`word` 条目必须带完整观测字段，检查器同时校验唯一 ID、字段完整与测试名存在）。

## 5. 性能预算与测量

开发基准：Apple M4／24 GB、Release 构建、固定字体和窗口。另设低配档案：8 GB 内存和集成显卡的 Windows 笔记本，无独立 GPU 的虚拟机或远程桌面，以及国产 CPU 与 GPU 的信创整机；1.0 预算同时报告这些档案的结果。Windows 和 Linux 分别固定硬件档案；不能直接把不同机器数字作为性能回归比较。每次测量记录电源状态、系统、源码、编译选项、语料散列和冷／热缓存条件。

| 指标 | 1.0 初始预算 |
| --- | --- |
| 冷启动到空白文档可输入 | p95 ≤ 1.5 s |
| 100 页常规输入到实际呈现 | p95 ≤ 50 ms |
| 60 Hz 下普通滚动帧时间 | p95 ≤ 16.7 ms |
| 100 页首屏可交互 | p95 ≤ 2 s |
| 1000 页首屏可交互 | p95 ≤ 5 s；全文处理可取消 |
| 空白文档进程内存 | ≤ 150 MiB |
| 100 页基准文档进程内存 | ≤ 350 MiB |
| 单架构安装体积 | ≤ 150 MiB，另列可选模型／字体包 |
| 空闲、AI 关闭 | 无持续重排、AI 任务或 Provider 请求 |

建立 10／100／1000 页三级固定语料，以参考软件和固定字体定义页数，兼顾正文、表格、图片和审阅。包含纯文本长段、首段编辑导致全文重排、末段编辑只影响局部等不同负载。

至少 30 次启动样本，输入与滚动至少 1000 个事件，记录原始样本及 p50／p95／p99／最大值。内存记录稳定 RSS 和加载峰值，GPU／共享内存另外记录；安装体积包括必须资源。首屏可交互、全文导入、全文分页分别计时，不能延后必要工作掩饰启动时间。开发 runtime-shader 构建的冷启动不能作为预编译着色器发行版的成绩。从 M1 起每个阶段门槛执行性能冒烟（如 20 页样例的打开与输入延迟），只用于发现回归，不替代 1.0 预算。

## 6. CI 与人工门槛

2026-10-18 用户决策：信创真机验证改为非阻塞待补验项，有条件时再执行；本例外覆盖信创真机上的运行、渲染、Fcitx、系统字体、性能和安装等专项，适用于 M0–M7 与 1.0 发布检查。相关构建和自动测试要求保留；缺少真机数据时公开标注“未验证／待补验”，不宣称真机兼容或性能达标，不阻塞其他开发、任务依赖、阶段验收或发布。

每次提交：文档追踪／链接检查、格式检查、clippy（含各生产 crate 的 no-panic lint）、依赖许可与安全公告检查、架构分层与文件系统访问白名单检查、单元及性质测试（含全命令恶意输入零 panic）、格式最小样例、三端构建；T005 通过后加入 ARM64 与 LoongArch64 Linux 构建。夜间：读取器 fuzz（自 M1 起）。阶段提交：完整语料、性能、恢复故障和跨软件对照。平台人工验收明确记录未覆盖项。

Linux GUI 构建不等于 Wayland／X11 启动成功；Mac 编译不等于 IME 与 VoiceOver 通过；Windows 的无窗口 CI 不能证明 Narrator 或真实打印工作。CI 配置存在不等于工作流已执行成功。

## 7. 阶段与发布检查

- M0：三端构建；Mac 真实窗口、中英文显示与 IME；统一字体场景 PDF 输出；信创构建与可用环境中的 GL／CPU 渲染退路验证（信创真机待补验，不阻塞）；语料框架可运行。
- M1：中文编辑—保存 DOCX—重开，正常和失败流程均通过；不可信文件预算与 fuzz 冒烟通过，受保护或强制修订文档不被绕过。
- M2：真实报告、富文本交换、PDF／打印，不能用静态样图替代；中文基础排版与 Word 参考结果对照。
- M3：合同审阅交换和接受／拒绝投影不变量通过。
- M4：本地可记录假 Provider 证明授权和关闭语义，普通编辑无网络依赖。
- M5–M6：专业文档与转换矩阵逐项验证，未知内容与损失可见。
- M7：三端真实运行、无静默数据丢失、恢复／打印／可访问性、性能和分发全部达标；信创真机专项按上述例外待补验，不阻塞发布。

1.0 还要求：无 AI 构建验证、许可证与资产来源完整、安装卸载／文件关联／签名／升级回退、恢复格式迁移、默认关闭遥测、公开限制与兼容矩阵。未满足门槛只可发布标明范围的预览版，不以调低目标代替修复；若确需调整产品范围，记录显式决策和理由。
