# JoyWord 产品规格

版本 0.3 · 2026-10-17 · 规范性文档。实施顺序见 [TASKS](TASKS.md)，技术细节见 [ARCHITECTURE](ARCHITECTURE.md)。

## 1. 产品目标与已确认决策

JoyWord 是 JoyOffice 的桌面文字处理应用，面向长期完整的 Office 套件。使用 Rust 与 GPUI，自研文档语义、格式读写映射、编辑事务和 Word 兼容分页规则。以中文办公、合同审阅、报告和中英文混排为早期重点；公文所需的文档网格、字符缩进和奇偶页页码在 M2 具备，完整 GB/T 9704 版式在 M5 验收。

| 决策 | 约束 |
| --- | --- |
| 平台 | 三端架构；macOS 先跑通；Windows、Linux 从 M0 进入构建验证，M7 必须真实运行验收；Linux 含信创发行版（统信 UOS、银河麒麟）及 x86_64／ARM64／LoongArch64，国产 GPU 与无 GPU 环境须可用 |
| 1.0 范围 | 以 DOCX 为中心的编辑、审阅交换、PDF／打印与恢复，含 DOC 与 WPS 文字（.wps）导入、RTF／HTML／Markdown／TXT 转换、加密与限制编辑、公文版式和信创平台；ODT、EPUB、归档 PDF、邮件合并、纵排与双向文本、DOC 写出、数字签名验证与创建在 M8（1.x） |
| 操作基准 | 固定版本的 Windows Word 桌面版（Word 2024 永久版：LTSC 或零售永久版，观测记录绑定确切 build）；中文文档互操作以固定版本 WPS 为并列对照；Mac 菜单、快捷键和窗口遵循 macOS 习惯 |
| 工作格式 | 新文档默认 Transitional DOCX；Strict 独立配置；逐步扩展其他格式 |
| 实现边界 | 核心独立实现；允许 ZIP、XML、Unicode、字体、图片、密码算法及底层 PDF 库 |
| AI | 默认关闭；用户配置本地或云服务；关闭是运行权限边界，不只是隐藏按钮 |
| 协作 | 离线编辑、文档交换审阅和本地历史先行；实时共同编辑另立规格 |
| 旧生态 | 旧版 DOC 先读后写；宏、OLE／ActiveX 先保留和安全预览，执行兼容另立项目 |
| 许可 | 仓库 MIT；第三方代码、字体、图标、模板分别保留其许可和来源 |
| 语言 | 默认简体中文，同时提供英文；UI 字符串从第一阶段外置 |
| 网络 | 普通编辑不依赖网络；遥测默认关闭；打开文档不自动访问外链 |

操作系统公开 API 与通用绑定可以使用；微软 Office 源码、Open XML SDK、Word 自动化及其他 Office 引擎不得承担产品内核。Word、WPS、LibreOffice 可在独立测试环境作为行为对照。

## 2. 用户工作流与交付边界

- M1：新建 → 中文输入 → 选择和基础格式 → 撤销 → 保存 DOCX → 关闭重开。
- M2：制作含标题、编号、表格、图片、页眉页脚和页码的报告 → 跨应用粘贴 → PDF／打印。
- M3：打开合同 → 修订／批注 → 交换给 Word 用户 → 接受／拒绝 → 正确写回。
- M4：选区授权 → Agent 生成修改提案 → 预览 → 以修订提交 → 撤销或关闭 AI。
- M5–M7：专业长文档、公文、多格式交换以及三端和信创平台的稳定发布。
- M8（1.0 之后）：ODT、EPUB、归档 PDF、邮件合并、纵排与双向文本、DOC 写出、签名验证与创建，以及复杂对象与 PDF 重建；不得用“保留”代替“编辑”。

文档、格式和排版内核应可在无窗口、无 GPU、无网络环境使用。早期版本需要显示明确版本及支持子集，不能以演示界面宣称产品功能完成。

## 3. 支持等级与完成定义

每项功能分别评估：读取、显示、编辑、写回、转换、交互。等级为完整支持、部分支持、保留支持、不支持；实际状态未验证时另标 `unverified`。

“完整支持”要求明确的子集定义、参考语料、正常与异常行为、格式往返及相关交互测试全部通过。未知内容原样保留不计作完整支持。任何兼容百分比都必须附样本范围、参考版本、字体、操作和失败分类。

## 5. 文档安全与异常行为

打开流程为识别容器、资源预算检查、解包／解析、关系验证、构造模型、生成诊断，再允许编辑。不得因为扩展名是 DOCX 就直接信任内部路径、XML 或对象。默认不执行宏、DDE、活动内容，也不自动访问远程模板、图片和链接。外部引用包括 HTTP(S)、UNC／SMB、WebDAV 和 file:// 路径；Windows 上仅解析 UNC 路径就可能泄露凭据散列。INCLUDETEXT、INCLUDEPICTURE、LINK 等外部域不随打开或 updateFields 设置自动更新。

可编辑模型之外保留原始包与未知 XML。无编辑保存可以直接复制原文件；编辑后的保存保持承诺语义及未触及的保留内容，不承诺 ZIP 全文件字节一致。未知对象涉及的修改无法证明安全时，应局部限制；无法建立安全边界时整文档只读。原子替换前按平台逐项核实元数据的可保留性（链接、权限、所有权、ACL、扩展属性、创建时间与来源标记）；存在无法保留或无法观测的项时明确列出，由用户选择另存副本（默认）或确认替换原件，不允许在不知情时丢弃。文档保护（只读、仅批注、强制修订、表单）和打开即修订的设置在对应能力实现前以只读或明确提示处理，不能让用户在不知情时绕过。

写入失败、磁盘满、权限变化、外部文件变动和错误密码都应返回可操作的诊断，并保留编辑会话。校验失败不得把部分文档标为“保存成功”。加密不等同于限制编辑；修改签名内容应明确使签名失效，不能继续显示有效签名。

## 6. 编辑与审阅行为

事务必须整体成功或整体失败。组合输入是暂态覆盖，提交才成为一次编辑；取消不产生修订或撤销项。连续打字可以合并撤销组，但不能跨越作者、审阅模式、文档版本冲突或显式操作边界；组合输入的每次提交、拖动手势和自动更正各自形成独立撤销步骤。输入层区分键入与粘贴两类来源：粘贴文本中的段落分隔不等同于按 Enter，不触发列表续接等按键语义。

向前删除按字素簇工作；退格的删除单位遵循平台惯例（部分文字可逐码点回退），但 emoji ZWJ、旗帜和肤色修饰序列始终整体删除；均不自动 Unicode 规范化。选区、批注、书签和修订范围随位置变换更新。删除批注锚点保留批注本身及可见失锚状态；不把“解决”误当“删除”。

无标记视图展示最终投影，原始视图展示原始投影；切换视图不改变保存的数据。接受／拒绝操作也是事务，可以撤销，但不自动生成针对自身的审阅修订。文档比较遇到已有待决修订时要求明确选择输入投影，不静默合并历史。

普通外部复制导出当前视图可见内容。内部保留修订、作者和批注是显式选项；隐藏的删除内容不得不经选择泄漏到普通剪贴板格式。剪切在剪贴板成功写入之后才提交删除。

## 7. 界面与排版行为

功能区按开始、插入、设计、布局、引用、邮件、审阅、视图组织；逐阶段开放真实功能。Mac 使用 Command 与系统菜单；Windows／Linux 使用对应平台快捷键。通过命令注册表共享功能区、菜单、快捷键和命令搜索行为。

打印布局首先实现；草稿、大纲、阅读、多页视图在专业文档阶段扩展。应用深色主题与文档纸张颜色分离，不得把 UI 主题写入文档。

缩放／DPI 只改变呈现变换。同一布局快照中的行断点、页断点、字形、图像与对象位置供屏幕、PDF 和打印使用。缺失字体及替代会影响分页，必须提示并进入导出诊断。分页期间页数可标“计算中”，不能将临时页数写为最终页码域。

## 8. AI、转换和长期边界

AI 的授权和关闭规则以 [AI 专题](AI.md) 为准。所有 AI 文档写入须通过相同事务入口；默认以 AI 作者修订提交。关闭不回滚用户已接受的内容，也不能收回先前发送到外部服务的数据。

转换统一先生成 ExportPlan 和损失清单。PDF 重建/OCR 是近似重建，不能称为原始 Word 语义的恢复。没有对应表达能力的目标格式必须提示修订、批注、公式、脚注、对象及布局损失。

1.0 不承诺 VBA／ActiveX 执行、云账户、实时共同编辑、移动端或完整 JoySheet／JoyDeck，也不承诺 §1“1.0 范围”中列入 M8 的能力。M8 扩大桌面兼容；M9 需要新的协作与套件规格，不预先声称稳定 ID 就等于支持 CRDT。

评审识别但尚未分配阶段的能力：简繁转换、水印与页面颜色／边框、行号、首字下沉、文档检查器（外发前清理个人信息）、受保护视图、DOCX 嵌入字体和 OFD 导出。纳入路线图时分配需求编号，在此之前不暴露入口。
