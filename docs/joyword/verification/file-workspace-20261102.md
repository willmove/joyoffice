# 文件页面与导出 Tab

2026-11-02，分支 `codex/joyword-1-0-completion`，基线 `95f632dee778d53bee67d9391c6c1b402861bca3`。保留前两批未提交的格式交换工作。本批按用户提供的 WordCraft 截图独立实现原生 UI 布局，没有读取或复用该应用源码；沿用已固定 GPUI 与图标资源，没有新增依赖。

## 实现与入口

点击主界面“文件”后打开左侧蓝色导航、右侧内容的文件页面。开始、打开、信息、打印、导出、选项为内容页；保存、另存为、关闭、退出路由原有操作。开始页保留邮件合并入口，打开页展示最近文件，选项页提供现有中英文切换。

“导出”页直接列出 PDF、DOCX、RTF、HTML、Markdown、TXT、EPUB 和 PDF/A-2b。DOCX 使用保留原包的另存作业；PDF／打印使用既有页面场景；文本格式直接进入对应损失确认和新路径选择，继续使用已提交快照及不覆盖发布器。未实现的 XML、ODT、LaTeX、PNG 没有伪造可用按钮。

文件页隐藏正文视口，并使用独立焦点与按键上下文，防止普通按键修改隐藏文档。“返回文档”和 Esc 恢复原正文与焦点；全局打开／保存／关闭快捷操作先退出文件页，再执行原有确认流程。只读／组合输入／版式限制和格式损失契约继续有效。

## 验证

`cargo xtask build joyword` 通过。`cargo xtask check joyword` 的 fmt、严格 Clippy 与 1315 项测试全部通过，零失败／忽略。新增回归验证八个格式入口的唯一身份、中英名称及实际非修改作业映射，保留文档代次与版本失效回归。

Windows 原生窗口已观察文件页导航、导出列表、TXT 直接进入专用损失提示并取消、Esc 返回正文、文件页按普通字母不修改隐藏正文。Markdown 从新列表生成副本，CLI 独立读回中文、emoji、格式字面量及未保存标记 `FILE_PAGE_1`，源文件逐字节未变，窗口仍显示未保存。键盘复验发现 GPUI 的 focusable 不自动加入 Tab 顺序，已补齐文件页 Tab 分组、控件 Tab 索引及 Tab／Shift+Tab 路由；最终构建实际执行 Tab→Enter 返回正文。详细原始截图和输出验证见 [本批索引](../validation/20261102-file-workspace/verification.json)。此前四种文本格式的完整语义回归继续见 [文本导出证据](text-exchange-ui-20261102.md)。
