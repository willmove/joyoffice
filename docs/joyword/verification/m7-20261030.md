本轮从干净的 main `0a6a5fdfd0c7261058b61376f2f6d4e386f38cb1` 开始，工作分支为 `codex/m7-validation-closure-20261030`。Windows x86_64，Lenovo 21TL，Intel Core Ultra 9 285H，32 GiB，Rust 1.98.1、Python 3.14.7。所有状态以实际证据为准。用户随后取消 GUI 时段确认要求，已执行当前 Windows 候选的桌面验证并修复三个缺陷；详见 [GUI 收口记录](m7-gui-20261030.md)。下列自动基线按执行先后保留，最终候选回归数字见 GUI 记录。

## 实现与修复

- **T208／T500／T702 段落缓存**：工作集超过预算时，旧实现顺序拟合的前缀 miss 会淘汰后缀即将使用的 fit，导致下一次重排再次全 miss。现在先计算本轮键集合，保护本轮所需项；陈旧键仍按 LRU 淘汰，装不下的 fit 参与排版但不挤走本轮有效缓存。默认仍为 32 MiB，内容／样式／字体／页码键与场景一致性要求不变。
- **T601 HTML 不可信输入**：Unicode 小写转换可以改变 UTF-8 字节长度，旧实现把转换后的位置用于切片原文，会在 `İ` 等输入上 panic 或截错表格／活动元素边界。改用 ASCII 大小写无关的原字节搜索；未闭合活动元素不再把其剩余 payload 显示为正文，孤立关闭标签不再吞掉后续正文。
- **T004／T103 特性语料**：五份 DOCX 改为 ZIP stored 成员，PNG 使用 zlib stored block，保持成员顺序与固定时间戳。更新登记散列，保留相同 XML 语义与原创来源，修复 stock zlib 与本机 zlib-ng 的压缩字节差异。未变更语料的 Office 验证等级。
- **T700 本机验证驱动**：[run_m7_validation.py](../../../scripts/run_m7_validation.py) 顺序运行文档、门禁、脚本单测、Rust／应用／AI 开关、实验和原生构建；每步保存命令、退出码、耗时、日志及散列，失败不会隐藏其余独立结果。
- **T701 原生控件语义**：通过现有 GPUI／AccessKit 接口给通用按钮设置本地化名称和稳定 author ID，给复选框设置 CheckBox 及开／关状态，给功能区设置 Toolbar／TabList／Tab 与当前选中状态。两个测试调用真实 Element 的 `write_a11y_info` 检查生成的 AccessKit Node；没有模拟一棵未接入 UI 的树。正文文字语义子树、范围动作、禁用状态和原生读屏仍未完成。仅给应用测试增加已锁定的 accesskit 0.24.1 直接依赖边，没有新版本或升级。
- **T702 分级测量**：[m7_performance.rs](../../../crates/joyword-layout/examples/m7_performance.rs) 与 [measure_m7.py](../../../scripts/measure_m7.py) 使用仓库 OFL 字体与固定 Latin 模型语料，每段显式分页，实际检查 10／100／1000 页；测量全量排版、首段／末段插入及撤销、预取消，逐次对照全量场景。保留原始 JSONL、nearest-rank 分位数与 Windows 50 ms 进程工作集采样。语料不是 Word 定义页数的混合报告；计时不含 GUI／GPU／实际呈现、文件导入、冷启动或滚动。
- **T703 便携预览产物**：[package_preview.py](../../../scripts/package_preview.py) 检查本机 PE／ELF／Mach-O 架构、生成确定性 stored ZIP、读回核对所有成员、生成逐文件散列、SPDX 源码依赖图与依赖自带 LICENSE／COPYING／NOTICE。图包含目标平台的 workspace build／dev 依赖，不能解释为每个二进制的精确链接图；缺许可文件单列。便携包不能作为签名安装器或升级回退的验收证据。
- **T704 发布检查**：[check_release.py](../../../scripts/check_release.py) 与 [checklist.json](../release/checklist.json) 覆盖 M0–M7 状态和 15 类观察，检查缺项、重复、文件散列与路径越界。默认不满足门槛退出 1；`--audit` 只允许有效的未完成清单被报告，不批准稳定版。信创真机待补验继续非阻塞，仍不标 passed。
- **T204／T603 CI**：unified-pdf 安装 qpdf 并设置 `JOYWORD_REQUIRE_QPDF=1`，已有外部导航复核在该作业中不能再因缺工具被跳过。四平台 build 增加 M7 发布审计与固定模型冒烟。修改后的远端 CI 尚未执行。
- **T204 读回测试适配**：发现 Git for Windows 的 `pdftotext` 是 Xpdf 4.06，不能读取 stdin 的 PDF。测试改为独立临时文件输入并保留 stderr，继续断言搜索文字、粗体不重复及标签；不把错误吞掉或关闭强制读取器。

## 三级模型测量

原始样本与 SHA-256 见 [测量摘要](../validation/20261030/performance/summary.json)。单位为 ms；工作集是 50 ms 采样获得的进程峰值，单位 MiB。

| 实际模型页数 | 全量布局 p95 | 首段事务＋增量布局 p95 | 末段事务＋增量布局 p95 | 采样峰值工作集 |
| --- | ---: | ---: | ---: | ---: |
| 10 | 13.247 | 0.668 | 0.733 | 12.20 |
| 100 | 129.266 | 6.599 | 6.983 | 33.38 |
| 1000 | 1410.253 | 2179.650 | 1109.598 | 224.00 |

每档 30 次全量排版；10／100 页每个首尾组各 1000 次插入／撤销，1000 页各 30 次，共 4060 次增量／全量场景核对。千页补充组与编译重叠，数据是开发机工作负载记录，不能作为隔离硬件的达标成绩。千页的 1000 事件扩展组没有完成，不计通过；一次更密集 Latin 候选因既有 shape-call 预算而拒绝，未提高预算。表内数字不含实际呈现、GUI 交互、冷启动、导入、滚动、稳定空闲 RSS 或 GPU，不关闭 QUALITY §5 的产品性能门槛。

复跑入口：

```sh
python scripts/run_m7_validation.py --out target/m7-validation
cargo build --locked --release -p joyword-layout --example m7_performance
python scripts/measure_m7.py --out target/m7-performance --samples 30 --events 1000 --hardware-profile "记录实际硬件、电源和负载"
cargo build --locked --release -p joyword -p joyword-cli
python scripts/package_preview.py --out target/joyword-preview.zip
python scripts/check_release.py --out target/release-readiness.json
```

最后一条在当前项目上应拒绝稳定版；使用 `--audit` 才是报告未完成清单。
健壮性实验要求生产目录为已提交状态；未提交开发时应在已核对生产树的隔离验证快照中单独运行，不能绕开该门禁。
