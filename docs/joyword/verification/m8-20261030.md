## 实现与修复

- 共用有界本地任务读取 UTF-8 CSV，支持 RFC 4180 引号、BOM／LF 扩展、Unicode、空值、前导零、逗号、转义引号和多行值；显式列映射和逐条预览。
- DOCX 中的 `{{字段}}` 经引擎事务反向替换，插入位置继承第一个花括号的字符属性。表格网格与周边格式保留，值不作为 XML 或新字段解释。导出新增软换行的窄支持，保留已有对象／修订导出的拒绝契约。
- 补严对象标量位置与未决段落／表格属性修订保护：解析位置保留对象标量，字段所在段落含已有对象明确拒绝，避免偏移或重建损失。
- 每批新建独立目录，create-new、sync、字节读回及 DOCX 语义复验；取消和错误清理本次目录。磁盘模板、CSV 和当前画布不被覆盖。
- 注册 `file.mail_merge` 命令，桌面有原生选择器、逐字段映射、逐条预览、生成和取消；中英文标签齐备。CLI 提供非交互 `merge` 与 schema 1 结果，无新第三方依赖或版本升级。
- GUI 发现长完成路径在状态栏裁切，改为短状态加原生完成对话框；路径全值进入原生可访问文本，Windows 视觉缩略长路径的行为如实记录。CSV 登记为 `-text`，干净 worktree 中也能复现含 CRLF／LF 的精确字节。
- [原创模板](../../../tests/fixtures/mail-merge/template.docx) 与 [CSV](../../../tests/fixtures/mail-merge/recipients.csv) 使用标准库确定性生成；[生成器](../../../scripts/make_mail_merge_fixtures.py) 的 `--check` 逐字节核对。CSV 规则依据 [RFC 4180 §2](https://www.rfc-editor.org/rfc/rfc4180)，未搬运第三方编辑器实现。
