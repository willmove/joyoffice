# 复杂 DOCX 表格导入、显示与编辑后续验证

2026-11-01，Windows x86_64、Rust 1.98.1。分支 `codex/joyword-open-rich-documents`，基线 main `5c0dd367`。这是 [只读打开修复](open-rich-docx-20261101.md) 的后续，不修改完整格式验收或里程碑状态。

## 实现

五份本机样例的整表降级主要由表格级边框、Word 的 rsid／paraId 提示属性、与表格相同的行对齐、默认底纹、单元格段落属性及软换行触发。导入器现在预检表结构，并复用正文段落导入器处理单元格文字、字体、段落、校对标记和文字修订。保留已有网格跨度、纵向合并、单元格边框／底纹／边距、行高、表头和一层嵌套表格。对不支持的结构仍保留原始 XML，保留不可信输入预算。

新增表格六边框和行插入修订模型。表格边框参与布局、语义比较、缓存键和规范化写出。行插入修订的作者和编号保留；可修改单元格文字并保留行标记，结构改动及修订接受／拒绝明确拒绝，桌面原始视图禁用。没有把行插入误当作整行文字插入。

页面布局支持单元格软换行和绝对缩进配合对齐，允许固定行距小于字体基线；软换行的各段共享排版工作预算。GUI 发现表头孤立于上一页后，新增表头与首个不可分割数据片段共同移页的规则，继续保留跨页重复表头。桌面对未实现的字体／样式属性使用独立兼容显示快照，保留段落 ID 和字符位置；未知对象显示方框，图片位置可能近似。持续显示兼容提示，原模型仍负责编辑和 DOCX 保存，简化场景不用于 PDF／打印等正式输出。严格排版接口没有静默清除来源属性。

单元格文字修改优先补丁更新原段落；选择该路径前，恢复所有修改段落并比较整个表格，证明表／行／单元格属性与拓扑没有变化。软换行成为文字分组边界，不把两侧文字移到同一个 XML 叶子。相同格式的 run 分割不作为语义差异；修订、链接或格式不同的 run 不合并。整段替换继承替换前的字符格式，保留表头字色、字号和加粗，仍为单次可撤销事务。

完全结构化的表格文档允许局部编辑，保护／MustUnderstand 等整篇限制不变。引擎在事务提交前验证所有锁定块完全未变，IME 候选事务同样继承锁。A 样例的保留对象及批注内容保持原有保护，另外 17 个同时有批注标记和文字修订的表头段落局部锁定，避免允许无法保存的修订重写。其余单元格继续可编辑。

保存后重新绑定递归更新表格和单元格段落的来源位置，同时按 XML 字节和命名空间映射保留句柄、映射回引擎稳定 ID 的局部锁。覆盖连续保存、保存后编辑和撤销后保存，避免第二次保存使用过期的字节范围。

依据 ECMA-376 Part 1 §17.4、§17.3、§17.13.5 独立实现。公开语义参考：[表格边框及冲突优先级](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.tableborders?view=openxml-3.0.1)、[软换行](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.break?view=openxml-3.0.1)、[行插入修订](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.inserted?view=openxml-3.0.1)。未搬运 Office 编辑器实现，未更改依赖或公共锁文件。

## 原生 GUI 验证

使用 `computer-use` 技能操作本机真实 GPUI 应用。全部编辑对象是忽略目录 `target/joyword-open-diagnostics/rich-gui/` 中的副本，五份原文件的前后 SHA-256 全部一致。

1. 分别打开 A、B、C、修订版、章节整合版，均进入可编辑文档而非只读文字投影，首屏标题及正文样式显示。
2. 在每份文档中查找量化交付基线表，滚动检查真实单元格、网格、底纹、边框和文字换行；A 和修订版还观察跨页表格及重复表头。
3. B、C、修订版、整合版替换表头文字，字色和加粗保留；A 在普通数据单元格插入验证文字，原有修订跟踪继续工作。B 另外执行撤销／重做并检查表头恢复。
4. 五份均通过原生 Ctrl+S 入口，确认写入测试副本，窗口显示保存成功并清除未保存状态。离线包检查确认每份只改变 `word/document.xml`，所有其他包部件逐字节不变，保存包含验证文字。
5. 修订版出现孤立表头后补回归并修复；最终构建重新打开该磁盘副本，已保存文字及白色加粗表头显示，表头与数据一起出现在下一页，上一页没有孤立表头。
6. 重启最终构建后再逐一从文件对话框打开五份磁盘副本。修订版用截图验证表头回读，其余四份通过 GUI 可访问性文档文本检查验证文字均存在；没有把仍驻留内存的会话当作重新导入。

截图、包检查摘要、原文件散列和产品日志均留在本机忽略目录，不提交私有文档或原文。重启时曾自动恢复出本轮整合版测试副本的会话，跳过这份已保存副本的恢复会话后才打开磁盘文件；恢复会话清理不作为本次通过项。

## 边界

本次交付可编辑的真实表格及保守保存路径，仍不宣称与 Word 完整分页、字体度量或所有图片锚定一致。A 的 17 个复合批注／文字修订表头以及原有保留对象段落暂不编辑；未解决的行插入修订不接受／拒绝，也不改表格结构。软换行两侧的文字编辑已验证，改变复杂段落的内联对象或格式边界仍可能被保存契约明确拒绝。未知 XML 不静默丢弃。

没有执行 Microsoft Word 对照、macOS／Linux、信创真机、实际输入法、物理键盘／读屏、完整结构编辑或正式发布验收。GUI 自动操作单独记录，不等于人工验收。
