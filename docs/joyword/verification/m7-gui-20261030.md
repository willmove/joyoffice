## 本轮修复

1. **M7-GUI-001，已修复**：Windows GPUI 原生 TaskDialog 默认采用传入的第一个按钮。旧顺序把 Cancel 放在第一位，虽然文案写了“另存副本（默认）”，Enter 却取消。现在由同一个按钮构造器将 Ok／另存副本置首、Cancel 次之，同步回答映射，过期版本与重探测检查保持。新增真实按钮元数据测试覆盖所有语言及两种风险提示；最终应用 85 项通过。修复后在真实对话框上用 Enter 复验成功，见观察 17–18。
2. **M7-GUI-002，已修复**：文本日志恢复旧实现用全文替换，删除未变的运行格式；Word 格式包还会因字符格式边界变化拒绝保存。恢复现在按 Unicode 标量寻找不重叠的公共前后缀，只重放变化区，范围转换为 UTF-16，不切代理对。六种 Unicode 插入／删除／替换／无变化场景核对文本、加粗、斜体、居中与可导出性；同一回归在旧实现实际失败。观察 20 保留失败，23–24 与磁盘读回证明修复。
3. **M7-GUI-003，已修复**：固定 recovered.docx 会在再次崩溃后撞上遗留 JoyWord 锁，而且旧代码先覆写该文件才检查锁。现在在恢复目录用 create-new 私有临时文件写入并同步基线，再保留为独立恢复副本。不移除或“过期”任何旧锁。回归在第一个恢复会话仍持锁时再次恢复，断言路径不同、旧文件／锁／检查点均不改变。

恢复仍是“原包基线＋已提交正文文本”的文本检查点；它不保存提交后的纯格式、表格结构、其他 story 或完整撤销历史。公共前后缀只保护变化区以外的已有格式，不能声称完整富文档恢复或断电保障。
