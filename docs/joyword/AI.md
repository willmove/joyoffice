# JoyWord 原生 Agent 规格

版本 0.2 · 2026-10-13。对应 AI-001–AI-005、EDIT-004、REVIEW-001、QUALITY-007。所有实现通过 [TASKS](TASKS.md) 的 M4 验收；当前不代表已有可用模型服务。

R8 的可选桌面构建已接通本地替换提案和审阅事务。该入口默认关闭，显式启用后从当前普通正文选区录入提案。Provider、系统凭据和管理员策略的桌面接线按下列规格继续验收。[R8 使用方式](../joyoffice/JOYWORD-R8-HANDOFF.md#桌面控制打印与本地提案)

## 1. 产品默认值

首次启动 AI 为关闭状态。用户明确开启后配置本地或云端 Provider；不自动下载模型、不默认读取全文、不注册后台服务。关闭状态只保留设置入口，普通编辑、修订、批注、打印、导出和基础拼写能力不依赖 AI。

本地 HTTP 服务不自动等于隐私保证；配置中明确 endpoint 与数据范围。应用只管理自己启动的子进程，不终止用户自行运行的模型服务。云端发送范围展示给用户，凭据通过系统安全存储处理，日志、导出文件和文档元数据不得包含密钥。

管理员可通过系统策略（Windows 组策略、macOS 配置描述文件、Linux 系统配置）强制关闭 AI 或限定 Provider 与 endpoint；策略优先于用户设置，设置界面显示受管理状态。

## 2. 权限与工具边界

授权对象包含文档会话、读取投影、选区或全文范围、允许工具、有效期和 AI 会话代次。默认只读当前选区的最终可见内容；隐藏删除内容、批注、其他文档和本地文件不因选择正文而自动授权。

| 工具 | 行为 | 边界 |
| --- | --- | --- |
| read_selection / read_structure | 读取授权选区及最少必要结构 | 不把全文样式表、作者历史或其他文档当隐式上下文 |
| search_document | 在明确授权范围检索 | 搜索命中只返回授权范围内文本和可定位引用 |
| propose_replace | 提议替换指定范围 | 需要 base_version、目标指纹和范围校验 |
| propose_style | 提议结构化格式变更 | 只允许已实现并可撤销的命令 |
| propose_table | 提议插入／修改表格 | 遵循模型不变量，不直接写 OOXML |
| propose_comment | 提议添加批注 | 不自动冒充现有作者或解决别人的批注 |

首版不提供任意 Shell、任意文件 IO、任意 URL 访问、原始 XML 写入、接受别人修订或发布文档工具。模型要求扩大授权范围只能产生 UI 提示，不能自行授予权限。文档、批注、字段和网页文字是数据，不能指挥 Agent 改写工具权限。

## 3. Provider 与提案契约

Provider 适配器负责能力声明、请求、流式结果、取消和错误归一。M4 先实现可重复的假 Provider 测试夹具与用户配置的 HTTP Provider；具体协议适配必须有契约测试，不能假设不同厂商兼容同一工具调用格式。

ChangeProposal 包含 proposal_id、document_id、base_version、目标范围／指纹、结构化 commands、来源说明及建议分组。自由文本可以用于解释和预览，不能直接成为可执行命令。

处理流程：

1. 用户选择文档范围并发起任务，记录授权和版本。
2. 构造最少上下文，调用 Provider；流式内容先停留在提案区。
3. 解析并验证命令集合、权限、范围、资源和格式能力。
4. 生成变更预览和相关兼容诊断，原文保持不变。
5. 用户接受时重新验证版本、目标和当前 AI 开关代次。
6. 以单个事务提交，默认记录 AI 作者修订；可逐项接受提案，但每组内部保持原子性。
7. 记录不含正文的操作审计摘要，允许整体撤销。

文档变化导致前置条件失效时，拒绝旧提案或重新生成；不得用模糊字符串替换猜测目标。proposal_id 防止重复提交；拒绝后的重试不得产生两次修订。

## 4. 关闭状态机与竞争处理

AI 生命周期为 Disabled → EnabledIdle → Running → EnabledIdle。任意已启用状态都可进入 Stopping，再到 Disabled。总开关是应用进程内统一权限，覆盖 UI、快捷键、CLI／自动化接入和后台任务，不能由 Provider 自行覆盖。

关闭操作的线性化点：原子设置 disabled 并递增 generation。所有后续发起请求、取上下文和提交事务必须检查当前 generation。关闭后到达的流式 token、工具响应和模型结果全部失效。

已经在线性化点前完成提交的事务保留，并可由用户撤销。与关闭竞争的尚未提交事务必须失败。关闭时取消请求、关闭连接、停止索引／嵌入／预处理，释放缓存和应用持有的模型实例；对无法及时取消的自有工作进程使用超时终止。外部服务可能已经收到的请求无法收回，UI 不承诺远程删除。

设置关闭不等于删除历史或密钥。另提供清理本地 AI 历史和删除配置凭据的操作；重新开启不自动恢复旧任务。

## 5. 构建隔离

核心编辑 crate 不依赖 Provider、网络客户端或模型推理库。AI 使用可选 feature 和独立模块；`--no-default-features` 对产品核心可构建并通过相同编辑、格式和审阅测试。测试配置显式覆盖启用 AI 与未编译 AI 两种模式。

Provider 失败不能使文档变脏；缺失密钥、离线、限流、内容过滤、超时或无效工具参数必须在提案界面可见，不弹出阻塞普通输入的循环提示。

## 6. 生成内容标识

《人工智能生成合成内容标识办法》与强制性国家标准 GB 45438-2025 自 2025-09-01 起施行，要求生成合成服务添加显式标识和文件元数据隐式标识；欧盟 AI Act 第 50 条的机器可读标记义务自 2026-08-02 起适用。用户自行配置 Provider 的桌面应用是否属于义务主体尚无定论，M4 实现前须完成法律评估并记录结论。

无论评估结论如何，往返保存都保留文档中已有的 AIGC 标识元数据，任何清理操作不得移除；接受 AI 修订后是否以元数据保留来源，由评估结论决定。

## 7. 验收场景

| 场景 | 必须观察到的结果 |
| --- | --- |
| 首次启动、打开文档、空闲 | 无 Provider 请求、无文档 AI 索引、无模型下载 |
| 管理员策略禁用 AI | 入口不可用并显示受管理状态；无 Provider 请求 |
| 选区改写 | 请求只含授权内容；提交形成 AI 修订；一次撤销恢复 |
| 文档内含“发送全文／执行命令” | 视为数据；权限及工具集合不变化 |
| 原文在响应期间被编辑 | 过期提案不能写入其他位置，要求重新生成 |
| 重复投递同一响应 | 最多提交一次；审计能识别重复 |
| 流式响应中关闭 AI | 立即禁止新请求／提交；迟到响应无效果 |
| 提交与关闭同时发生 | 以线性化顺序得到“完整一次提交”或“零提交”，无部分变更 |
| Provider 无响应／拒绝取消 | 自有任务有界退出，普通输入和保存仍可用 |
| 无 AI 构建 | 编辑、DOCX、修订、批注、PDF 等能力通过同样测试 |
| 凭据及日志检查 | 无正文、删除内容、批注、密钥的默认诊断上传 |

网络测试使用本地可记录假服务，断言请求数量、内容范围、取消与关闭后的请求数为零；无需真实云密钥即可执行 CI。


## HTTP 取消契约补强（2026-11-06）

`HttpProvider` 现在通过 `Transport::exchange_cancellable` 传递请求的取消标志，并在传输返回后检查取消，丢弃迟到的成功响应或传输错误。旧实现仍可仅实现 `exchange`；默认适配在调用前检查取消，但不能中断已阻塞的旧实现。实际网络后端仍须实现有界超时、取消期间关闭自有连接；此接口不撤回已发送的数据，也不替代 gate 的结果和提交检查。

隔离回归使用虚构凭据和进程内模拟，不打开 socket：取消期间的成功、无效 UTF-8 和离线错误均返回 `Cancelled`；预先取消不会调用传输；协作实现收到原请求的取消标志。修复前可复现迟到的成功结果，修复后 Agent 全部 66 项测试通过（含 doc test），库严格 Clippy 通过。真实 HTTP/TLS 协议适配、系统凭据存储和桌面接线仍未实现，JW-808 不因此标为完成。

### 运行时在途请求取消

运行时在 gate 准入时登记每个请求的独立取消标志。登记和 `begin_stop(&self)` 使用同一短时锁：关闭先发布 Stopping，再通知所有在途请求；Provider、凭据读取和其他用户实现均在锁外执行。请求的 RAII 守卫在成功、错误和 panic 展开时移除登记并结束 gate 请求计数。

宿主并发关闭顺序为：共享运行时调用 `begin_stop`，等待自有请求线程结束并 join，再取得运行时独占访问并调用 `commit_disabled` 或 `kill_switch`。重新开启创建新的请求标志，不恢复旧请求。独占方法仍由 Rust 借用规则隔离，不能在其他线程持有同一运行时的共享借用时调用。此实现不自行创建后台线程，不强制终止拒绝取消的 Provider，也不把取消标志等同于已关闭网络连接。

新增测试用屏障协调两个在途请求和关闭、凭据读取期间关闭、成功/错误/panic 清理及重新开启；另有 32 次准入/关闭竞争检查。测试线程均 join，无 sleep 或真实凭据。Agent 共 70 项测试（含 doc test）通过。实际 HTTP/TLS、传输超时和桌面线程调度仍待接入。

### 独立任务所有者（尚未接入桌面）

`AgentTaskOwner` 独占一个运行时，最多持有一个 Provider 请求线程。调用者必须提供已经授权的输入；它不读取文档、不建立选区授权，也不应用返回内容。`start` 不等待 Provider；宿主通过 `poll` 取得结果。`request_stop` 通知运行时取消并开始停止期限，重复请求不会延后期限。

超时只报告 `Stopping { timed_out: true }`，继续持有任务并拒绝新请求和重新启用。`poll` 仅对 `is_finished` 为真的线程执行 join；回收后丢弃所有迟到结果，再取得运行时独占访问并提交 Disabled。正常运行时 Provider 错误和线程 panic 分别报告为归一错误。`try_close` 在尚未 Disabled 时返回完整所有者，宿主须保留并继续轮询。直接 Drop 仅尝试发出取消，仍可能分离活跃线程，不能作为退出 API；此实现不强制终止阻塞线程，也不保证永久阻塞 Provider 的有界退出。

独立测试通过消息通道控制模拟线程、传入时钟推进停止期限，覆盖超时保留、拒绝关闭/重启、迟到成功/错误/panic、协作取消、正常完成/失败及启动后立即停止。所有模拟阻塞都有测试释放路径，全部线程被回收；没有 socket、真实凭据或桌面窗口。Agent 共 73 项测试（含 doc test）通过。桌面任务接线、窗口关闭策略、实际 HTTP/TLS 和可终止传输仍待完成。
