# 高级设计与备注的 a11y 节点重复修复

2026-11-02。基线 `d564ad8eab0532863284d8a59ba3fb6dff962238`；本轮在 Windows x86_64 / Rust 1.98.1 debug 上验证，不改变完整阶段验收状态。

## 复现与根因

在备注区已展开时，进入“设计”，再展开“管理母版与文稿”。辅助功能客户端连接并激活 GPUI 的 a11y 树后，原实现触发：

```text
gpui-pre-0.3.10/src/window/a11y.rs:415
Duplicate a11y node id: #10165069213016462132
```

本轮先只扩展原生验证路由、保持生产控件不变，使用 `--startup-smoke --require-a11y` 复现该断言；进程退出码为 `0xC0000409`，没有成功标记。单纯绘制窗口而未连接 a11y 客户端的测试不会触发此路径，因此不能用其通过结果代替节点验证。

高级设计的备注框与底部备注框绑定同一个 `TextareaState`；高级表单的主题强调色和背景色也分别与上方精确值框绑定同一个 `InputState`。输入实体除了文本还持有焦点、布局和无障碍语义，同一实体同时渲染为两个可编辑控件会复用节点身份。只修改显示标签或开发者分配的 accessibility ID 无法解决这种状态复用。

## 修复

- 高级设计的备注、强调色、背景色使用独立输入实体，保持两处控件均可编辑。
- 用由 Editor 持有的订阅双向同步草稿；值相同时不回写，避免循环通知和重置正在编辑一侧的光标。草稿同步不执行文档命令。
- 从模型加载/刷新字段时明确更新两个输入实体，覆盖绘制期间切页刷新，不依赖该阶段的输入通知来补齐另一个视图。
- 撤销/重做后刷新全部文档字段，修复“文档备注已经撤销、备注框仍显示旧值”的相关问题；备注提交沿用原有修订检查与单命令历史。
- 为两个备注控件提供不同的辅助功能标签与开发者 ID；高级表单输入补充与可见标签对应的 aria label。

## 自动与原生验证

```powershell
cargo xtask check joydeck --validation
$env:JOYDECK_TEST_A11Y = '1'
cargo test -p joydeck --locked --features validation --test recovery_process native_startup_and_all_ribbons_fit_the_default_ui_thread_stack -- --ignored --nocapture
Remove-Item Env:JOYDECK_TEST_A11Y
cargo xtask build joydeck
python scripts/check_gates.py
python scripts/check_docs.py
```

专项测试需要可用桌面、图形设备及连接到测试窗口的辅助功能客户端。设置 `JOYDECK_TEST_A11Y` 后，进程最多等待 30 秒激活 a11y；缺少客户端时不产生成功标记，测试失败。未设置该变量时仍执行原有 16 个工具栏的启动/绘制检查；该模式不宣称完成无障碍验收。

本机实际结果：

- Deck 分产品 fmt、严格 Clippy、194 项常规测试通过；原生桌面测试仍为显式 ignored，已单独执行。
- 要求 a11y 激活的专项测试通过 1280×800、980×800 两种布局。覆盖空选择、预设形状、表格选择；每种布局反复开合高级设计和备注区 12 次。
- 从真实生成的 a11y 树检查节点 ID 唯一，以及两个备注、两组配色输入在显示时分别存在且仅出现一次，防止仅通过隐藏控件或丢弃节点绕过断言。
- 两个方向分别输入不同备注和配色值，检查草稿同步及文档修订不变；通过生产命令与渲染路径验证备注单次保存、撤销/重做、往返切页、陈旧备注拒绝与刷新。
- 工程门禁和文档检查通过；默认功能 GUI/CLI 已重新构建。

## 普通窗口核验与边界

普通 debug 构建使用隔离偏好目录启动，通过 computer-use 打开设计/高级设计并保持备注区显示。实际键盘输入底部备注、辅助功能“设置值”编辑高级备注均可双向同步；高级强调色编辑同步至上方精确值框，两个备注节点同时出现在辅助功能树中，未再出现重复断言。

最终默认构建另用隔离偏好/恢复目录核验：从高级备注输入并点击“保存备注”，聚焦画布后按 `Ctrl+Z`，两个备注框同时清空；按 `Ctrl+Y` 后两框同时恢复同一文本。两个区域在整个过程中均展开，辅助功能树中的两个备注节点均保留。

本轮是 Windows 的该组合验证，不代表完整读屏认证、输入法矩阵或所有工具栏的无障碍审查；macOS/Linux 尚未实测本次修复。未修改 GPUI 依赖、公共库或文档格式。
