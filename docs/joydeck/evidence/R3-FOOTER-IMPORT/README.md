# JD-305 页眉页脚导入摘要与逐页保留

2026-11-06，Linux x86_64，无桌面验证；基于主干 `7b37ad4c884706087983d352d4a11148040de02a`。

## 模型与范围评估

当前 `Presentation.header_footer` 保存文稿级标志、页脚文字、固定日期文字、自动日期格式和标题页隐藏选项；PPTX 导入从各页实际占位符推导这个摘要。实际页脚内容、样式和日期字段仍在各页形状中。普通和保留 PPTX 写出依赖这些形状，不能把单独修改摘要视为完整的“应用到所有幻灯片”。现有引擎没有完整文稿页脚命令，界面也没有整份页脚编辑器。

因此本批不创建或替换各页占位符，不尝试从混合文稿猜测统一页脚、标题页策略、备注／讲义设置或 OOXML `p:hf` 的完整继承。先补上确定的导入遗漏：

- 页眉占位符置 `header = true`。
- 自动日期占位符中的第一个 `datetime…` 字段保留到 `date_format`，包括来源中未知的日期标识，不自行改成默认格式；与现有日期字段识别规则一致。
- 固定日期文字与自动日期格式分别保留，可共存于混合文稿。第一页页脚文字仍是摘要默认值，其他页面的独立文字／字段不变。

## 验证

两项新增回归先在原实现失败：已有页眉却得到 `header = false`，`datetime13` 被读成空格式。修复后覆盖：

1. 两页不同页脚（中文／emoji），一页固定日期、另一页自动日期，并含页眉和页码占位符；摘要完整而逐页内容保持。
2. 只编辑第一页现有页脚后走 `export_preserving` 保存与重开：第二页模型和 `ppt/slides/slide2.xml` 原始字节保持，自动日期格式保持，输入包仍读回原始基线。
3. 13 种标准自动日期、`datetime`、`datetimeFigureOut` 和未知 `datetime99` 保留原标识；非日期 `slidenum` 不误识别为日期格式。

真实桌面操作、完整页脚 UI、应用到全部页、标题页隐藏、备注／讲义页脚和跨办公软件互操作均未验收。该批为读回与保留写回基础修复，JD-305 继续开放。
