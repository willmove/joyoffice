# JoyDeck R2 保存冲突与失败复验

2026-11-05，从 `69880cc` 构建 Apple M4 / macOS 27.2 ARM64 Release 验收包，在仓库外中文空格路径运行。[包和运行时指纹](verification.json)

同一进程中的多个保存作业可以同时编码和写入自己的临时文件。最终指纹校验和发布使用同一个临界区。同一源指纹的两个冲突保存只有一份发布，另一份保留冲突状态。临时文件只在成功独占创建后清理，失败和成功路径均检查目录无残留。

- `cargo test --locked -p joydeck-shell --test editing` 的 15 项通过。并发回归使用相同的预期指纹提交两份不同内容，验证只有一份成功且字节完整。现有测试同时覆盖无效目标、外部改动、拒绝覆盖已有另存目标、保存快照之后继续编辑仍保持未保存，以及撤销到已保存内容后恢复干净状态。Shell 严格 Clippy 通过。
- 通过真实文件菜单保存不可变的测试 PPTX，macOS 拒绝原子替换。原件和修订不变，未保存标记保留，目录无临时文件。[替换失败实屏](save-atomic-replace-failure.png)
- 将另一个有效 PPTX 写到已打开的源路径后再点保存，外部字节保留，当前四页与原修订仍在。取消关闭提示后会话保持，使用原生面板另存新 `.joydeck` 后由包内 CLI 读回四页。[外部修改实屏](save-external-change.png)

`cargo xtask check joydeck` 的格式、严格 Clippy 和 899 项产品测试均通过，归档与包内 1,805 个校验值一致。

同进程保存发布受临界区保护，其他进程的写入通过发布前的指纹核对发现。跨进程的锁协议与设备、文件系统资格按后续平台任务记录。
