# 已有页脚的只读状态与 UI 安全边界

2026-11-06，在 `fix/joyoffice-safety-integration@bf289bb9` 上继续。本批实现引擎公开函数 `existing_footer_summary(&Presentation)` 及 `ExistingFooterSummary`，供后续 UI 使用。没有新增 UI 控件、自动同步或新增占位符，没有修改导入文稿的保存行为。

## 已确认的模型语义

实际页脚在各页形状中，`Presentation.header_footer.footer_text` 只是导入摘要，不足以表示所有页面。读取该字段后默认“应用到全部”会掩盖逐页差异。现有 `set-existing-footer-text` 只处理已有、可见、未锁定的简单页脚，不代表为所有页面创建页脚。新增占位符还需要解决布局/母版继承、原始关系与未知 XML、p:hf 可见性和标题页规则，不能复制母版对象或猜坐标。

## 本批接口

只读查询直接遍历实际页脚，返回：

- `text: Some(value)`：所有已有页脚具有相同文字；`Some("")` 明确表示统一空文字。
- `text: None`：实际文字混合，不能解释为清空，也不能拿第一项预填后自动提交。
- `targets`：已有占位符数量；`pages_with_footer` / `pages_without_footer`：页面覆盖数量。一页多个占位符不会重复计作多页。

无页脚时返回明确错误。分组、锁定、隐藏、非文本形状、多个段落/run 或动态字段拒绝，复用编辑命令的同一结构校验助手；超过 256 个目标同样拒绝。查询不依赖文稿摘要、不修改模型、选区、修订或撤销历史。查询是结构状态，不替代对具体输入文字的 `Session::validate`：64 KiB/单行输入、1 MiB 输出及最终模型预算仍由提交预检检查。

UI 已有依据的安全默认：打开或取消不提交命令；混合状态保留，只有用户明确输入替换文字后才可提交；明确显示“更新已有页脚文字”的作用范围和未覆盖页数，不能标为“所有页新增页脚”；提交前仍校验当前会话，失效或复杂内容不能静默跳过。

## 尚不能从现状确定的产品行为

新建缺失页脚的默认规则仍需要选择：

1. **建议：仅依据当前版式的唯一、有效 Footer 占位符补建**，逐页明确选择，无法唯一解析、继承可见性不明或含未知关系时拒绝；保留已有页脚。适合优先保护导入文件，但部分页面无法自动补建。
2. **由用户指定位置和样式新建普通页脚文本框**，无需依赖版式 Footer；需要新的设置与预览，且必须明确它与占位符继承语义不同。

当前页与全部页应是明确的独立操作，不应根据文稿摘要自动决定。本批不擅自实现上述任一新增策略；不改变既有文稿。
