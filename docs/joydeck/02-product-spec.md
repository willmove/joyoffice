# 产品目标与交付范围

版本：规格 2.0，2026-10-29。Windows M0 与 M1 基础只读切片已实现；后续范围仍是目标，证据见 STATUS 与实施记录。

## 1 产品定位

JoyDeck 是离线优先的桌面演示文稿编辑与放映工具。核心目标是在 Windows、macOS、Linux 上，以 Rust + GPUI 提供稳定、清晰、响应及时的编辑体验，并让用户能够可靠地与 PowerPoint 交换常用 PPTX 文档。

目标不是在首个版本复制 PowerPoint 全部功能，也不把 GPUI 选型本身作为性能结论。产品价值用实际工作闭环衡量：打开真实文稿、修改文字与图形、保存而不丢内容、准确放映、导出可分享结果。

### 目标用户与场景

| 用户 | 工作场景 | 关键成功条件 |
|---|---|---|
| 日常演示作者 | 从空白或模板制作 10–50 页报告 | 易发现的操作、中文输入、排版、快速撤销 |
| 现有 Office 用户 | 打开已有 PPTX，做小范围修改后交回 | 不静默丢数据，兼容报告清楚，修改可追溯 |
| 教师与讲者 | 本机编辑，外接投影演讲 | 双屏隐私、计时、翻页、媒体和断连恢复 |
| 设计与内容人员 | 多对象排布、主题与版式复用 | 坐标精确、缩放流畅、母版和颜色语义一致 |
| 自动化用户 | CLI/MCP 生成、转换或检查文稿 | 同一命令语义、错误可机器读取、文件访问可控 |

### 基础工作闭环

1. 新建或打开文档，看到加载进度与兼容性提示。
2. 通过缩略图/大纲定位页面，在画布中修改。
3. 撤销与重做；格式面板和命令入口保持状态一致。
4. 保存原生文件或另存 PPTX；重新打开确认修改和未编辑内容都保留。
5. 以全屏演示或导出 PDF/图片交付。
6. 遇到应用关闭、设备变化和文件错误时，有可理解的恢复方式。

## 2 对标基准及实现知识边界

采用 Microsoft 365 桌面 PowerPoint 的公开功能语义作为主要参照，兼顾 Windows 与 macOS 的平台差异。每项兼容声明绑定明确的公开语义、格式子集与测试环境。

Microsoft 官方跨平台表显示，桌面、网页和移动端的动画、放映及编辑能力并不等同。因此需求逐项标注版本范围，不使用一个模糊的“PowerPoint 全兼容”承诺。[官方功能比较](https://support.microsoft.com/en-us/powerpoint/compare-powerpoint-features-on-different-platforms)

可公开验证的实现事实包括 OOXML 包结构、关系和字段语义。PowerPoint 内部对象模型的具体存储、渲染后端、线程调度、增量绘制和协作算法属于未公开细节。本文的 CommandBus、Scene、缓存和历史设计是 JoyDeck 方案，不声称是 PowerPoint 的内部实现。

| 对标领域 | 保留的用户能力 | JoyDeck 实现方向 |
|---|---|---|
| 母版与版式 | 全局设计、占位符、页面局部覆盖 | 文档级继承模型与依赖失效 |
| 图形文字编辑 | 直接操作、精确格式、撤销 | 统一命令与交互事务，共享文字布局 |
| PPTX | 多 part、关系、主题、媒体和扩展 | 标准驱动导入、带保留数据的包图 |
| Morph | 跨页对象匹配和插值 | 显式匹配优先、可预测 fallback |
| 演讲者模式 | 演讲者看备注，观众看画面 | 两个 GPUI 窗口共享只读 ShowSnapshot |
| 无障碍 | 替代文字、逻辑阅读顺序、可操作 UI | 文档语义与应用 AccessKit 两条链 |
| 自动化 | 可脚本控制文档 | 同一领域命令用于 UI、CLI 和 MCP |

PowerPoint 的母版工作流可包含多个母版、关联版式、主题及页脚；本项目保留这些语义，采用自己的视觉系统。[母版官方说明](https://support.microsoft.com/en-us/powerpoint/training/customize-a-slide-master)

## 3 功能优先级

- **P0**：数据安全、主要创作闭环、基本文件兼容、输入及运行可靠性。对应阶段必须完成后才可关闭。
- **P1**：日常桌面工具的重要完整性，包括母版、表格、图表、放映、打印与自动化。纳入 Beta，但分阶段完成。
- **P2**：高保真长尾、录制、高级动画、复杂图表、更多格式、协作与生态扩展，允许在 M14 以后交付。

优先级不是顺序号。M11 的媒体 P1 不阻挡 M7 的基础 MVP；同样，数据安全 P0 从 M2 起不能推迟到 M13。

## 4 版本边界

| 版本 | 阶段 | 可以承诺的体验 | 明确的范围边界 |
|---|---|---|---|
| 技术预览 | M0–M1 | GPUI 窗口、诊断、文稿浏览与兼容提示 | M1 默认只读，不能误导用户保存修改 |
| 编辑预览 | M2–M6 | 原生保存、图形、中文文字、图片、主题、母版、基本工作区 | PPTX 写回在 M7 才正式成为承诺 |
| MVP | M7 | 常见图文文稿的编辑、原生/PPTX 往返、基本静态放映、PDF/图片导出 | 复杂表格图表可预览或保留，尚不保证完整编辑 |
| Beta | M8–M13 累积 | 表格图表基础编辑、动画双屏、常用媒体、自动化、打印和三平台发布 | 未覆盖效果有能力标签、预览和降级报告 |
| 后续 | M14 | 长尾格式、录制视频、硬件媒体、协作/扩展评估 | 以独立决策和成本评估排期 |

MVP 的“保留对象”必须对用户可见：能否显示、编辑、保存保留分别说明。不能让一个无法渲染的未知对象像被删除一样消失，也不能把截图当成可编辑图表。

## 5 首版排除项

首版不要求 Web、移动端、FreeBSD、完整 Office 插件/VBA 执行、OLE 嵌入程序编辑、IRM/加密、旧二进制 PPT、完整 ODP、高级 3D 场景、实时多人协作、云端账户、Copilot 等价 AI 服务、全量 SmartArt 布局或完整视频录制编码。

文件中相关内容的处理仍需要规定：能保留则保留，不能保证保留则阻止无提示覆盖；宏不执行；外部关系不自动联网；不能解密时保持原文件不变并给出明确错误。这些是基础文件行为，不是隐含承诺完整支持相应功能。

## 6 用户体验原则

1. 操作结果可见：选择、焦点、修改状态、加载、导出和保存都有清晰反馈。
2. 文件最重要：取消不能留下半次编辑，失败不能破坏已有文件，关闭不能静默丢弃修改。
3. 渐进披露：常用操作在工具栏；对象特定操作在上下文和属性面板；全量命令可搜索。
4. 直接操作与精确输入并存：拖拽与数值面板触发同一事务；多个选中对象显示混合值。
5. 美观来自一致性：统一密度、间距、字体、图标和状态设计，界面明暗与幻灯片主题分离。
6. 离线可用：文档默认留在本机，网络能力由用户显式开启。
7. 不确定性透明：缺字体、未知对象、媒体解码失败和格式降级都有定位到页/对象的说明。

## 7 可衡量的成功指标

### MVP

- 不安装 Office 也能启动、创建、保存、重新打开自建文稿。
- 通过指定语料的中文 IME、文字范围、组合对象及历史测试。
- 常用 PPTX 样本达到 07 中的 C1/C2 门槛；所有有损情况可定位。
- M4 的指定画布场景有真实加速或显著增量收益，不能仅展示静态窗口 FPS。
- 本地 Windows 持续运行；macOS/Linux 在 M0 起持续构建，M7 前完成基础编辑实际冒烟。

### Beta

- 三个平台都通过常用操作、恢复、中文输入、剪贴板和放映测试。
- 覆盖受支持对象的导入、显示、编辑、保存四个维度；核心语料无静默丢失。
- 60Hz 交互、首屏时间、内存、转场及媒体达到 09 的预算或正式缩小功能支持范围。
- 每个发布包在干净机器安装并运行，使用发布包本身验收。

## 8 开发与范围控制

阶段通过依赖和验收定义推进，不先铺一批永远不能运行的基础设施。新模块先交一个真实的窄切片，再扩大覆盖。任何模型/场景提取都保留上一版可运行路径，直至替代路径达标。

新增要求必须附功能编号、阶段、测试和兼容影响。超出本规格的外部服务、收费组件、格式扩展先形成决策，不阻断已有范围的开发。阶段估算见 10；独立实现工作量需按已验证切片重估。
