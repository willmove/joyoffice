# GPUI 界面与交互规格

本章规定用户可见行为及 GPUI adapter 的边界。以 FR-APP、SLD、GEO、TXT 为主要需求，详细任务在 11。

## 1 界面组成

采用适合桌面演示创作的熟悉结构，原创视觉语言。工具区可采用紧凑 Ribbon 式分组与上下文标签；不逐像素照搬 PowerPoint，也不复制其图标、主题或模板资源。

| 区域 | 内容 | 状态与交互 |
|---|---|---|
| 起始页 | 新建、最近文档、打开、恢复列表 | 缺文件可移除；恢复数量和失败提示可见 |
| 标题区 | 文档名、dirty、保存状态、窗口按钮 | 区分正在保存和已保存；平台标题栏行为规范 |
| 快速访问 | 保存、撤销、重做、搜索 | tooltip 显示平台快捷键与禁用原因 |
| 主工具区 | 文件、开始、插入、设计、转场、动画、放映、审阅、视图 | 只展示当前阶段可用组；小窗口折叠组而不缩成不可点区域 |
| 上下文工具 | 形状、图片、表格、图表、媒体 | 根据选择类型切换，混合选择显示共同可用项 |
| 左侧导航 | 缩略图、节、大纲 | 虚拟列表、拖动反馈、页码、隐藏标记、兼容警告 |
| 中央画布 | 页面、pasteboard、标尺、参考线和 overlay | 视口独立于文档坐标，光标/手柄保持可点击尺寸 |
| 右侧面板 | 属性、选择、动画、评论、设计等 | 单主面板+可切换标签；可调宽和隐藏 |
| 备注区 | 当前页备注 | 高度可调；使用相同文档事务，不与画布同时持有输入焦点 |
| 状态栏 | 页码/节、语言、检查状态、视图、缩放 | 提供精确缩放输入和 fit |
| 任务中心 | 打开、保存、导出、字体/媒体任务 | 进度、取消、失败详情、结果位置 |

默认桌面尺寸目标 1280×800 logical px；最小可用窗口 960×600。比这更小可收起缩略图/属性并保留切换入口，不把应用直接拒绝启动。三平台非客户区尺寸不同，不将窗口外框当成内容区域。

建议首版尺寸：标题/快速访问约 32–40 px，工具标签 32 px，工具内容 72–104 px，导航默认 224 px（160–360），属性默认 300 px（260–440），状态栏 26–30 px。所有尺寸是起始设计 token，M0/M6 根据实际字体、DPI和可用空间校准。

## 2 GPUI Kit 复用范围

| 能力 | 优先复用 Kit | 应用自有实现 |
|---|---|---|
| 通用控件 | Button、Input、Select、菜单、弹窗、tooltip、toast、color picker 等 | 命令 binding、参数及业务校验 |
| 列表/布局 | 虚拟列表、滚动、split/dock primitives | 幻灯片 ID、节、缩略图调度、跨列表拖动 |
| 工作区 | panel/dock 行为和主题机制 | Ribbon 分组、上下文规则、文档窗口关系 |
| 文字 | 普通输入框、搜索/属性输入 | 画布富文本、表格单元格与文档文字布局桥 |
| 绘制 | Element/canvas/paint path、图片显示 | DrawingML 场景、对象命中、选择手柄和动画 |
| 数据表/图表 | 可用于 UI 数据编辑与诊断 | 文稿中的表格/图表模型及跨格式渲染 |

Kit 官方提供主题、虚拟列表、dock 等通用能力；应用需要把这些能力接入文档语义。[GPUI Kit 概览](https://gpui-kit.com/)

不把 Kit 的代码编辑器或富文本控件强行用作整张幻灯片的文字排版器；它们无法自动满足占位符、字体替代、段落继承、autofit 和 PPTX 输出。

## 3 视觉与主题

建立语义 token：surface/window/panel/canvas/selected/focus/error/warning/text/muted/border；状态色不由各个面板硬编码。明暗主题只影响应用外壳，幻灯片始终按文档颜色显示；另设明确的灰度预览，不把暗色模式改写到文稿。

基础间距使用 4/8/12/16/24 px；密集属性行高度约 28–32 px，普通交互目标尽量不小于 28 px，触控专用放大模式后续评估。font family、fallback 和字号由 UI 字体策略统一选择，不能依赖仅 Windows 安装的字体。

所有颜色弹层都区分主题色、标准色、最近色、透明度；主题色选择保存 ColorRef，不提前固化为 RGB。多个对象属性不同显示“混合”，用户只改一个字段时不覆盖其他字段。

图标采用受审核的开放许可或原创方案，文本 label/tooltip 保证可理解。文档本次不提供任何图标、字体、主题预览或样例资源。

## 4 输入路由与焦点

路由优先级：系统 IME → modal → 当前文本输入控件 → 当前画布富文本 → 当前画布工具 → 全局命令。某层消费事件后不继续触发下一层。

明确 focus scope：窗口、工具区、缩略图、画布、备注、属性、弹窗、命令面板。工具按钮点击可暂存文字选择；改变文字格式后恢复原编辑焦点。模态弹窗 trap 焦点，关闭后回到原有效元素；原对象已删除则回画布。

Tab 在画布对象选择态按对象逻辑顺序切换，文本态按列表或表格规则处理；离开画布进入 UI 有明确快捷键/焦点路径。禁止全局捕获 Tab 导致用户无法走出画布。F6/Shift+F6 可作为主要区域切换默认，平台冲突时提供替代。

键绑定分 macOS 与 Windows/Linux：Cmd 与 Ctrl、Option 与 Ctrl 的逐词移动语义不同。菜单显示用户真实平台组合键，不向引擎传简单“cmd||ctrl”后丢失来源差异。

### 编辑与手势事务

- 按下时建立交互快照；捕获指针直至释放，即使移出画布仍能完成或取消。
- 拖动只更新预览/交互状态；释放提交一个历史步骤；Esc 恢复原始文档和选择。
- 拖动时关闭窗口、切页或焦点丢失，先完成确定的 cancel/commit 策略，不能遗留 dragging 标志。
- Shift 锁定方向/比例；Alt/Option 中心缩放；复制拖动在 M5 固定平台组合键。数值输入可用更精确路径完成同一结果。
- 矩形框选采用方向/包含规则固定并提示；命中优先级为手柄、当前编辑元素、最上层可见未锁对象、页面/pasteboard。
- 触控板缩放保持指针下文档点不动；惯性平移与翻页区分，缩放页面不能因轻扫误翻页。

## 5 画布与坐标

Document pt、GPUI logical px、physical px、OS screen coordinates 四套坐标显式命名。fit 是视图操作，不能改变对象尺寸。DPI 切换需重建 appropriate raster cache，但不改变文档位置和比例。

选择框、旋转柄、连接点和参考线使用固定 logical 视觉尺寸；对象真实边界和命中几何使用文档坐标。旋转文本、嵌套组、裁剪图片与非均匀变换不能只按轴对齐矩形命中。

编辑显示页面外对象，放映/缩略图/导出裁剪页面。滚动条描述可视工作区而不修改页面大小；fit 重新居中要有明确动作。

## 6 富文本与 IME 适配

GPUI 输入接口、marked text、选择范围和 caret screen rect 的具体 API 以锁定快照为准，M0 做最小实验，M3 接完整 CanvasTextInput。协议至少表达 surrounding text、selected range、marked range、replace range、commit、cancel 和候选位置查询。

引擎保留原 TextSel/Composition 的语义。adapter 每次交换索引时必须标注 UTF-8 bytes、UTF-16 units、Unicode scalar 或 grapheme cluster，并测试跨代理对、ZWJ emoji、组合音标、汉字和换行的映射。任何无效范围均做可控归一化或报错。

预编辑文字可以暂时显示于编辑模型，但不能成为未提交恢复快照/导出中的半个字。保存、关闭、切页、进入弹窗和外部命令先按统一策略 settle 或 cancel composition；不能对同一提交同时响应普通 text 和 IME commit，造成重复字。

候选窗口跟随实际文字插入点，需包含画布缩放、组变换、窗口坐标和 DPI；跨显示器移动后重新查询。字体面板普通输入和画布输入不同时持有 IME ownership。

文字的光标命中、选区底色、baseline、下划线、预编辑 active segment 与 glyph 布局共用同一结果；不通过 GPUI 默认 label 重新排一遍造成位置漂移。

## 7 属性面板与对话框

属性 draft 在 Enter、失焦或明确应用动作提交；Esc 还原未提交输入。滚轮拖动数值控件可合并连续操作；每次鼠标像素移动不新增撤销步骤。超范围输入保留用户文本并说明有效范围，不悄悄变成 0。

颜色/渐变等连续预览有明确开始/完成/取消。需要批量修改多个对象时使用同一事务，部分对象不适用要给结果摘要。文件对话框取消后不改变当前路径和 dirty 状态。

提示分三类：非阻断 toast、可定位的任务/兼容报告、必须决策的 modal。不要用消失的 toast 承担丢内容警告或保存失败的唯一反馈。

## 8 无障碍与本地化

GPUI/Kit 使用 AccessKit 提供 UI 语义。自绘画布仍需应用提供对象、文字和选择的可访问节点；画出图像不等于读屏可用。稳定 element ID 与用户可读 name 不同；role/name/state 也不自动提供键盘行为。[GPUI 无障碍说明](https://gpui-kit.com/docs/accessibility/)

UI 无障碍与文稿无障碍分别验收：前者检查菜单、焦点、属性、画布对象；后者检查 slide title、alt text、装饰对象、阅读顺序和导出语义。图层排序与阅读顺序独立存储，持久化模型变更需要版本升级。

简中与英文从 M0 起纳入字符串资源。命令 label、disabled reason、错误、数量/单位和日期统一格式化；文稿中真实文字与日期字段语言不随 UI 切换自动变动。RTL UI 镜像为后续扩展，但不能阻止现阶段编辑 RTL 内容。

## 9 UI 性能与测试

缩略图、对象清单和大纲虚拟化；屏外页只保留数据，不全部创建 GPU 图片。hover、caret blink 和焦点切换不触发整页重新栅格化。诊断 overlay 展示真实 frame/paint/raster/upload 时间，不只刷新一个 FPS 数字。

使用稳定语义 ID 定位真实生产控件，按 Kit 提供的测试能力做状态、布局、焦点和 accessibility 验证；GPU 截图及 OS IME 仍需实际平台验证。`test-support` 只在开发测试依赖启用，与生产依赖使用相同源和版本。[Kit 测试指南](https://gpui-kit.com/docs/test/)

每次改动工作区布局、文本、菜单或放映窗口，都要查看实际运行截图/画面，检查 100%、125%、150%、200% DPI 和至少两种窗口尺寸。自动快照需要固定字体和时间，不能用不同系统字体的像素差异直接判定文档语义错误。


## M8 已实施工作区（2026-10-30）

浅色原生标题/功能区、紫色强调、全高虚拟缩略图、居中灰工作台、上下文格式栏、底部缩放与备注抽屉已替换早期诊断按钮堆叠。文件/图片操作使用系统选择器；高级交付和母版控制按需展开。表格主格命中、范围、分隔线、共用文字IME、剪贴板和事务路由在生产画布可操作。实现及真实截图、实际窗口尺寸/平台范围见 [30](30-m8-implementation-report.md)。没有实测的DPI/读屏/平台保持待验证。


## M9/M10 本机PowerPoint对照后的实现（2026-10-30）

在本机PowerPoint实际打开原创文稿采集开始/插入/动画/放映，按1600×900窗口复核JoyDeck。透明标题栏/快速访问30px、页签32px、功能区80px；缩略图栏250px、缩略图约200px宽，首张约y150、白色画布约y166。开始按剪贴板→幻灯片→字体→段落→绘图排列，主命令大图标/名称、次命令紧凑成行；插入与动画/放映遵循任务分组。采用现有Lucide全量资源补齐缺图标，保留独立JoyDeck品牌。

默认收起格式栏，图表/图示/表格上下文页签随对象出现；底部折叠备注32px、状态栏/缩放保留。系统字体列表、形状菜单、表格尺寸对话框和新增图表/图示/时间线是真实入口。演示者窗口限制图像尺寸，备注独立可滚动；观众无备注，退出后恢复编辑焦点。真实截图、发现/修复与仍存在的密度/外观差异见 [审查记录](evidence/m10/ui-reference/audit.md)，软件验证见 [32](32-m10-implementation-report.md)。仅本机窗口和单有效显示器，其他DPI/读屏/全键盘与全平台验收仍未完成。
