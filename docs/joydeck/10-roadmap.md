# 分阶段开发路线图

本路线按真实可运行的纵向切片推进。每个阶段包含 UI、数据、错误和验收；不能连续几个阶段只写基础库而没有桌面产物。M0 Windows 原生技术预览已实施且可运行，待完整验收；M1 基础只读浏览切片已交付，完整阶段仍进行中；M2剩余实现已补齐，Windows自动验证通过，完整M2待验收；macOS 最终包 M0–M3 原生 adapter 回归、系统拼音与 35 项测试通过（见[24](24-m3-macos-verification.md)）；M3 文字预览已交付，完整 M3 未通过（遗留见[23](23-m3-implementation-report.md)）；M4 核心 Scene/GPUI 切片已实现，45 项测试及本机 release 验证见[26](26-m4-implementation-report.md)，完整 M4 仍待验收；M5 图片创作增量已实施，50项测试及本机证据见 [27](27-m5-implementation-report.md)，完整M5仍开放；M6 文稿设计增量已实施，60项测试和本机证据见 [28](28-m6-implementation-report.md)，完整M6仍开放；M7 文件交付增量已实施，66项测试与本机证据见 [29](29-m7-implementation-report.md)，完整M7/MVP仍开放；M8表格与工作区改造本机受支持范围done，79项测试、GUI/系统拼音/PowerPoint编辑往返及最终包见 [30](30-m8-implementation-report.md)；M9基础图表/图示本机受支持范围done，见 [31](31-m9-implementation-report.md)；M10软件子项与单屏双窗口验证done，完整双屏/硬件/AT-12门禁开放，见 [32](32-m10-implementation-report.md)；M11/M12已有可运行开发切片，完整阶段仍开放，见[33](33-m11-implementation-report.md)、[34](34-m12-implementation-report.md)；M13本机资格化与M14三个可运行扩展已实施，完整Beta及扩展池仍开放，见[36](36-m13-implementation-report.md)、[37](37-m14-implementation-report.md)。详见 [实施记录](17-m0-implementation-report.md)。

## 统一阶段完成定义

1. 该阶段任务及对应 FR 验收通过，新增能力在真实 GPUI 桌面可操作。
2. `cargo build --locked -p joydeck` 实际链接成功；适当的 fmt/clippy/领域/集成检查通过。性能结论使用 release 构建。
3. 提供可运行分发目录或测试包，说明 OS/架构/feature/版本及运行方法；不得只交源代码或 cargo check 截图。
4. 按 [12 验收手册](12-acceptance-playbook.md) 完成 3–10 分钟阶段演示，记录预期与实际、已知限制、日志和必要截图。实际测试产物链接到各阶段实施记录。
5. 本阶段引入的读写、取消、错误、undo/redo、焦点和资源清理有覆盖；此前核心场景继续通过。
6. 保留上一阶段构建/版本作为回退点；更新 STATUS、任务、需求追踪与风险。未实测平台保持未验证。

M0 先实现上述命令入口。后续建议 `cargo xtask stage Mx` 选择相应自动检查，`cargo run --locked -p joydeck` 启动交互验收。目前 check、stage M0/M1/M2/M3/M4/M5/M6/M7/M8/M9/M10/M11/M12/M13/M14 已实现；stage 只执行构建与自动测试，不能替代真实桌面及整阶段验收。后续阶段入口随实现补齐。

## M0 工程与技术风险验证

**目标**：让用户立即看到 JoyDeck 的 GPUI 原生窗口，同时尽早发现依赖、输入、绘制与平台风险。

工作：创建最小 Rust workspace，锁 Kit/GPUI/toolchain，增加诊断页面；验证按钮/菜单/焦点、简中与英文、普通 IME、自绘 path、CPU RGBA 图像显示、两个窗口、DPI、后台任务和实际测试入口。保留所选 API 的版本记录和 spike 结论。

**演示**：运行应用，切换主题语言、输入中文、拖动窗口到另一屏/改变 DPI、显示测试路径和图像、开关第二窗口、取消后台任务。此时诊断内容不是演示文档模型。

**退出门槛**：本机实际 build/run；三平台至少 native build，真实窗口测试状态可追踪。没有解决的 IME/API/GPU 风险必须有 owner、截止阶段及可运行替代路径；不能默认为框架自带就已完成。

## M1 只读文稿查看器

**目标**：可以打开独立定义的 `.joydeck` v1 与受支持的 PPTX 子集，浏览真实页面。

按公开格式和独立数据模型实现最小读取与 CPU 预览，解析与栅格化在后台执行。提供打开、进度/取消、缩略图虚拟列表、页导航、fit/zoom、兼容报告和缺字体提示，能力统一标记只读。

**演示**：打开一份 20 页 native 和一份 PPTX，浏览、缩放、查看不支持对象；大文件加载中取消并继续操作其他窗口。

**退出门槛**：损坏/超限不崩溃；晚到渲染不串页；首屏和内存有基线；没有任何貌似可保存的编辑入口。AT-01、AT-02、AT-15 通过。

## M2 基础编辑与数据安全

**目标**：从空白开始画简单图形，并能安全保存重开。

独立实现命令/事务/工具/历史；实现新建页、缩略图多选与排序、基础形状、选择/移动/缩放/旋转、基础格式和数值输入。定义 `.joydeck` 容器，提供原子保存、dirty close、恢复，使用 CPU 页面加独立 overlay。

**演示**：创建三页，插入矩形和文本框对象，拖动和改色，撤销重做；保存并重开；修改后选择取消关闭；制造受控异常退出再恢复。

**退出门槛**：没有静默丢修改，交互取消不留半次编辑；保存旧 revision 后新编辑仍 dirty；恢复不覆盖原文件。AT-03、AT-06、AT-14 通过。

## M3 富文本与中文输入

**目标**：真正可制作中文图文页面，不能只在属性输入框里输入中文。

画布文本/表格未来复用的 CanvasTextInput、rich run/paragraph、列表、选择、导航、剪贴板文字、font fallback、composition 与 GPUI 平台桥。M0 验证过的 API 在此连接真实文档布局和历史。

**演示**：中英/emoji/组合音标混排，中文预编辑和取消，格式化局部文本；焦点进属性后 Delete 不删画布对象；一次 IME 提交只需一次撤销。

**退出门槛**：AT-04、AT-05；所测平台实际 IME 结果有记录；未测平台不得标通过。文字 glyph/caret/选区保持一致。

## M4 画布加速与性能闭环

2026-10-30：现有模型的 Scene/GPUI 路径、glyph mask、图片和局部 fallback 已实现，本机 release 对照及开放条件见 [26](26-m4-implementation-report.md)。完整阶段未验收，M3 前置缺口仍保留。

**目标**：实际减少编辑时 CPU 整页栅格化，并看到拖动缩放改进。

从已有渲染逐项提取 Scene，保留 CPU 参考；实现 GPUI 常见 path、图片、文字绘制及 effect fallback；增量缓存、局部失效、任务合并与预算，加入真实诊断和 benchmark。

**演示**：同一 BENCH-EDIT 在 CPU 基线与新后端下拖动/缩放，显示 raster/upload 计数、p95 延迟和缓存；打开复杂效果页查看 fallback 不错序。

**退出门槛**：满足 06 的 R2 与 09 的阶段性能门槛；图形/文字确实进入加速路径，overlay-only 不触发整页重绘；错误/设备丢失受控。AT-07、AT-15。

## M5 图片剪贴板与对象操作

2026-10-30：图片资源/导入/裁剪/剪贴板、对齐分布增量见 [27](27-m5-implementation-report.md)。组/连接符等尚未实现，完整阶段未验收；M0–M4前置缺口继续保留。

**目标**：完成日常图文排版的主要直接操作。

文件/拖放/系统图片粘贴，crop、SVG 受限渲染、组、连接符、预设实现、对齐/分布、层次、锁定、选择面板、自由路径和独立的路径合并能力。每次实现必须检查 scene/GPU 与 CPU 输出，不能只接上按钮。

**演示**：粘贴截图、裁剪、组合、连接两个框并移动、对齐、选区锁定、保存重开。

**退出门槛**：三平台剪贴板当前验证结果可见；媒体引用复制不悬空；非法图片/路径受控；AT-08、AT-03。

## M6 母版主题与完整工作区

2026-10-30：共享历史/同文档双窗口、设计继承/文字占位符、备注/节/查找替换和跨文档页复制增量见 [28](28-m6-implementation-report.md)。完整母版/格式面板、文字扩展/工作区、本地化/读屏及完整阶段验收仍开放。

**目标**：从“能改一张图”提升为“能组织完整文稿”。

母版/版式/占位符、主题/颜色/字体、节/大纲/备注、跨文档粘贴、多窗口 ViewSession、查找替换、字段和完整本地化，补齐键盘和可访问语义。

**演示**：改变母版标题样式，观察继承页与直接格式差异；跨文档粘贴保留源格式/目标主题；两窗口独立选择、共享内容与历史；切换简中/英文。

**退出门槛**：无悬空 layout，主题修改正确失效，active doc 不串写，已有 UI 无硬编码新文案；AT-09、AT-05、AT-14。

## M7 文件交换与基础 MVP

2026-10-30：原包保留/受限文字写回、静态PPTX、PNG/JPEG/PDF与全屏静态放映见 [29](29-m7-implementation-report.md)。40份原创合成公共读取及PowerPoint单样本只读打开已验证；完整公开往返/授权外部语料/三平台与MVP退出条件仍开放。

**目标**：可实际交付常见图文演示文稿。

完成 PPTX 写入和源包 sidecar 保留，关系校验、兼容报告和有损保存策略；加 PDF/图片输出、简单全屏放映、外部文件冲突处理和 MVP 语料库。原生格式升级和重开回归在本阶段完成。

**演示**：打开一份经授权 PPTX，修改文字和图片，另存并在 JoyDeck/PowerPoint 重开；导出 PDF/PNG；从当前页全屏翻页并退出。

**退出门槛**：07 的最小语料集与 C1/C2 子集声明成立；三平台基本编辑实际运行；AT-10、AT-11、AT-12 的静态部分、AT-14、AT-15。MVP 不声称表格图表、媒体和复杂动画已经全面可编辑。

## M8 表格

**目标**：可编辑结构正确、能交换的常用表格。

增删行列、编辑单元格、Tab 导航、合并拆分、边框/样式、尺寸、TSV 粘贴，衔接 M3 的文本和 M4 的 Scene。包括 native/PPTX 往返，不能只完成 UI 表格网格。

**演示/退出**：制作预算表、合并标题、粘贴 TSV、撤销、保存重开；AT-16，无半提交表格或合并引用错误。

## M9 图表与 SmartArt

**目标**：用可编辑数据生成常见图表，提供限定范围结构图。

基础图表、数据网格、元素/样式、图表 workbook/chartex 保留；SmartArt 文本面板及基础布局、转换为组。未知图表/布局保留与告警。

**演示/退出**：修改系列数据看到曲线变化，保存 PPTX 重开；切换流程图布局并撤销；AT-17，数据缓存与嵌入部件一致，不把未知内容错误替换为普通图表。

## M10 动画转场与双屏放映

**目标**：能带常见构建动画在正确的投影屏演示。

时间轴、动画面板、基础转场、Morph 子集、演讲者模式、屏幕选择/交换/热插拔、笔和自定义放映、计时与暂停。保留原复杂效果为逐项扩展，不能一批注册菜单就标完成。

**演示/退出**：观众屏无备注，演讲者看下一页；点击构建、暂停/恢复、Morph、跳转、拔掉外屏；AT-12 完整通过，实际双屏结果和支持子集表齐全。

## M11 音视频

**目标**：支持清楚限定的常用媒体，失败不影响演讲。

按最小依赖逐个引入 probe/container/codec，音频输出和同步、视频帧、控制条、seek、循环、跨页、设备更换；后台有界解码和原文件参数往返。

**演示/退出**：播放 1080p30 指定 H.264 MP4、seek/暂停/换页、跨页音频，切换输出设备；AT-13 和 BENCH-MEDIA。不将硬件解码或视频导出混入本阶段基础承诺。

## M12 审阅自动化与输出完善

**目标**：使产品适用于批处理、审阅及正式交付。

按 M12a 评论与阅读顺序、M12b CLI/控制/MCP、M12c PDF 矢量/打印/其他导出三个可运行小增量推进。沿用所有阶段完成定义，不等全部实现后才提供一次产物。

**演示/退出**：评论/解决、检查 alt text；CLI 与 UI 得到相同模型；MCP 连接；打印预览/PDF 矢量比较；AT-18、AT-19、AT-11 扩展。认证、文件根和超时语义通过，不把传输跑通等同于协议完整。

## M13 三平台 Beta

**目标**：实现可安装、可恢复、可维护的跨平台版本。

扩充真实语料、稳定性长跑、无障碍/复杂文字、GPU/显示器/音频矩阵、打包签名、更新与回退、完整用户帮助。M13 是全面验证与修补，不能把 M2 起就需要的数据安全拖到这里首次做。

**演示/退出**：干净三平台安装包各完成核心闭环；≥100 份语料，规定性能/内存门槛，长会话无静默数据损失；AT-20，全量发布阻断项关闭。没有硬件或证书的目标不得记作正式通过。

## M14 后续扩展

按用户价值分别立项：更多动画/图表/SmartArt、真竖排/公式、二进制 PPT/ODP/宏保留、视频导出/录制/硬件解码、讲义备注母版、无障碍 PDF、协作和插件、更多平台。

每项有独立需求、依赖、API/许可评估、可运行增量和验收，不把整个 M14 定成无限“全面 PowerPoint 对齐”任务。

## 依赖与范围变更规则

核心链为 M0 → M1 → M2 → M3 → M4 → M5 → M6 → M7。M8/M9、M10/M11、M12 主要子域有独立内部切片，但只在共享数据契约稳定后安排。是否多人并行由后续开发组织决定，本次规划不启动任何开发代理。

遇到 GPU/字体/PPTX 复杂度超预期时，先保留可运行 fallback，再明确缩小声明范围，或增加命名的子阶段。不得把一个未通过的核心门槛移到“未来优化”然后标完成。改动模型 schema、渲染路线或依赖快照时更新 13 的决策记录并重跑相关阶段验收。
