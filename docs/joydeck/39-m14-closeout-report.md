## 范围与变更

本轮收尾覆盖已交付切片的比较、自动化和恢复缺陷及前序回归。M14原定义是独立立项功能池，长尾格式、全量动画、高级文字、三方合并等尚未实现的大项继续按原任务推进；本轮不据此关闭完整M0–M14父阶段。

- T-M14-06：新增对象接受原先总是追加到顶层，参考文稿中的底层/中间对象因此改变遮挡关系。现在以参考文稿中相邻的共有对象定位，采用同一复合事务保留稳定ID与图层；不改变目标中既有对象的相对顺序。正序/逆序逐个接受后重比无差异，每次仅增加一个修订并可独立undo/redo。图片依赖缺失时整个事务拒绝，不改变文稿或历史。
- T-M14-06：原先只比较媒体资源ID，漏报同一资源的扩展名/探测信息变化。现在比较ID与元数据，比较摘要不复制媒体字节；指纹仍保护完整语义版本。媒体元数据只报告，未增加自动合并或资源迁移。
- T-M12-05/07：远程 `document.new/open` 成功后，客户端现在跟随返回的DocumentId。新连接也通过已认证服务查询当前ID，避免读到凭据文件中创建服务时的旧ID。原先CLI连续命令、MCP摘要或后续连接会指向旧ID，导致操作失败。失败响应保持旧ID，显式target仍须匹配，重复operationId继续使用服务端去重结果。
- T-M12-05/07：包级测试进一步复现两个CLI进程共用默认 `cli-0`，第二次调用报 `id-conflict`。自动ID现使用每次调用的128bit随机命名空间，连接查询和MCP摘要也生成独立ID；用户显式operationId仍原样用于服务端去重，不改变未知执行结果时的重试契约。
- T-M2-07/08：恢复会话与保存暂存名增加进程内序号，避免同进程并发或时钟回拨时仅靠时间戳命名。恢复测试目录改用已有私有随机目录分配器；新增16个并发恢复会话的独立租约/快照回归。

修复前的新增测试分别复现媒体漏报、图层错误与远程ID未更新。完整基线检查还暴露两个恢复测试取得相同时间戳并共用目录，现场目录同时含两个测试的快照；单独重跑曾通过，随后修复目录隔离及生产命名，没有降低断言。

仅修改Deck engine/shell与Deck验证脚本；产品依赖边界、公共模块、Cargo.lock、构建规则与schema均未改动。没有本轮Word实现变更。
