# 净室实现与需求基线

版本 2.0 · 2026-10-29。JoyDeck 依据用户需求、公开标准及自建样例独立设计和实现。

## 知识与材料边界

- 输入：本项目 FR/AT、ECMA-376/OPC/PresentationML/DrawingML 公开规范、依赖的官方 API、合法取得文稿的可观察行为。
- 实现：独立命名的数据结构、算法、命令和测试；不使用第三方产品的实现细节、内部模块映射、命令注册清单、资源或品牌作为设计输入。
- 依赖：仅经清单记录的通用开源库；记录用途、版本、许可证及来源。公开标准与第三方库代码的来源分开记录。
- 样例：项目自建；外部文稿须记录授权、来源与参考环境，不能从来源不明的资源推断许可。

## 工作方法

1. 先写用户可观察行为、错误条件、格式子集和预算，再实现。
2. 使用公开格式字段定义解析，不通过兼容私有实现的内部类型推进开发。
3. 每个纵向切片均编译、实际启动 GPUI 桌面应用并记录日志；测试替代不了启动。
4. 将未知特性标为未支持并定位到页面/部件；只读打开失败或取消时保留当前文稿。
5. 维护 FR → 任务 → AT → 实施证据，只有实际验证过的条件才能勾选。

## 透明性

本次整改建立后续工作的材料边界，不能追溯性证明既有资料的作者知识隔离。文档清理与独立新增实现有记录，不将“删除引用”本身当作净室证明。不得把资料清理解释为对第三方许可义务的豁免。

## M1 独立切片

A：定义 `.joydeck` v1 的最小只读模型、受限容器读取与自建样例；编译并启动。
B：依据 OPC 关系及页面顺序读取 PPTX；受限后台 CPU 预览；编译并启动。
C：接入打开/取消、页面列表、导航、适应窗口与 25–400% 缩放、兼容报告；编译并启动实际文件浏览。
