## 变更与边界

`save_original` 的公开签名不变。一次调用内部顺序是：扩展名与 `ExportTarget` 一致，否则 `Io { stage: Validate }`；然后 `check_source` 完整重跑（锁、路径解析、身份、精确字节）；然后比对来源；然后能力矩阵；列表非空则返回 `ReplacementUnavailable` 且零写入。列表为空才进入发布函数。当前每个目标的矩阵都非空，所以公开函数到不了发布。

来源规则（W10 的 `ExportPlan::origin_bytes() -> Option<&[u8]>`，定义未改）：

- `None`：`ReplacementUnavailable`，blocker 只有 `OriginBindingUnproven`。W10 没有公共构造器能造出 `None`，这条是防御分支，集成测试覆盖不到。
- `Some` 且与 `SourceStamp` 字节不等：`SaveOriginalError::OriginMismatch { path }`。版本相等不算同源。
- `Some` 且逐字节相等：继续看能力矩阵。

能力矩阵与 W07 相同，来源不再塞进矩阵：

| 项 | 本构建 | 写入前 blocker |
| --- | --- | --- |
| permissions | Preservable | 无。`mode & 0o777` 只在发布函数里用 `set_permissions` 写回 |
| ownership | Unix：ObservableNotPreservable；非 Unix：Unobservable | `UnpreservableMetadata` 或 `UnobservableMetadata` |
| acl／extended_attributes／provenance_marks | Unobservable | `UnobservableMetadata` |
| creation_time | ObservableNotPreservable | `UnpreservableMetadata` |
| links | ObservableNotPreservable | `UnpreservableMetadata`；`nlink > 1` 再加 `LinkedSourceSemantics` |

没有新的 xattr／ACL 依赖。无法保证的元数据仍在任何临时文件之前拒绝。

Unix 发布函数（`publish_original`，非公开）在 blocker 为空时执行：同目录 `.joyword-replace-*` 临时文件 → 写 `plan.bytes()` → `sync_all` → `verify_bytes` 逐字节回读 → 恢复权限位 → 硬链接前用完整 `SourceIdentity::difference` 对照 stamp → 预留 `.joyword-replace-bak-*` 后 `hard_link` → 备份回读等于 stamp 字节，且目标仍是同一 `dev`+`ino`（`same_object`；硬链接会改 nlink 与 ctime，这两项不在备份确认里比）→ `rename` 覆盖目标。rename 之前的失败只删备份，原件字节留在原 inode。rename 之后的失败用 `SaveOriginalError::io_published`，回执耐久性是 `FileSynced`；成功回执是 `FileAndDirectorySynced`。非 Unix 分支若被调用，返回 `ReplacementUnavailable { AtomicReplaceUnverified }`，不写文件。`std::fs::rename` 在 Windows 上不替换已有文件，这条保持拒绝，没有伪造成功。`io_published`、`same_object` 和 Unix 发布实现包在 `cfg(unix)` 里，避免非 Unix 构建把它们当成未使用代码。回执路径是 stamp 路径：macOS 上 `open_source` 会把 `/var` 规范成 `/private/var`，测试对 `stamp.path()` 比较。

直接调用发布函数的单元测试（绕过矩阵，用来证明步骤本身，不代表公开保存成功）：同源编辑计划发布后权限位 `0o640` 写回、目录只剩目标、同预算 `DocxSession` 重开字节等于 `plan.bytes()`、旧 stamp 的 `check_source` 失败；CreateTemporary／Write／SyncFile／Verify／RestorePermissions／Backup／VerifyBackup／Publish 注入失败时原件不变且备份被删；Cleanup／SyncDirectory 失败时错误带 `FileSynced` 回执且目标已是新字节。

`save_export_copy` 行为不变。`verify` 改名为 crate 内 `verify_bytes`，`sync_directory` 改为 `pub(crate)`，供发布路径复用。

公共枚举增量（既有变体保留）：

- `ReplacementBlocker::AtomicReplaceUnverified`

- `SaveOriginalError::Io` 增加 `published: Option<SaveOriginalReceipt>`

- `SaveOriginalError::is_origin_mismatch`、`published`

`SourceIdentity::same_object` 是 `pub(crate)`。
