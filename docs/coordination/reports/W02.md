关键机理发现（均实测）：

1. **0.2.2 的真实缺口只有一个**：`Window::paint_glyph` 与
   `TextSystem::resolve_font(&Font)→FontId` 本就公开；外部字形绘制被
   `GlyphId(pub(crate) u32)` 挡住。一处可见性补丁即打通（IMPLEMENTATION
   中"0.2.2 不可能"的表述可据此更精确）。
2. **macOS add_fonts 不认 TTC 的非 0 face**：走 `CGFont::from_data_provider`，
   TTC 只装载 face 0；唯一名注册静默失败后 resolve 落到 fallback。必须先
   抽取目标 face 为单字体文件（表字节不变，有测试）。
3. **同名冲突**：不同字节顶替系统家族名时解析不漂移（系统胜出），
   即按名解析无法绑定字节，冲突风险坐实；散列唯一名 + resolve 可绑定
   （正控制度量与系统逐位一致）。
4. `resolve_font` 失败会静默走 fallback 栈，唯一名不存在时不会报错，
   只会得到别的字体——正式实现必须校验解析结果（如 get_font_for_id
   或度量比对）。

## 接口或依赖提案

建议 ADR-010 采纳（A 路线，最小变更）：

1. gpui 来源：crates.io 0.2.2 + vendored 单行补丁（`vendor/PATCH.md`
   的 diff），以 `[patch.crates-io]` 固定；待上游（gpui-pre 线）发布
   平台 crate 或我们决定切 git rev 时再整体迁移。
2. 屏幕链路约定：注册前对 TTC 抽取目标 face + 按 FontKey 散列改写
   name 表（`probe/src/name.rs` 可整体迁入正式 crate，保留规范来源
   注释）；`add_fonts` 后用唯一家族名 `resolve_font`，并以
   `get_font_for_id`/度量比对校验未落入 fallback；绘制用
   `paint_glyph(origin, font_id, GlyphId(gid), size, color)`，y 偏移
   符号约定与 PDF 侧一致（场景 y 向下、字形偏移取负）。
3. 构建：无完整 Xcode 的机器用 `gpui/runtime_shaders` 特性（同根仓库
   apps/joyword 现行开关）。
4. 偏离说明：本实验 workspace 把根仓库的 `unsafe_code = "forbid"` 放宽
   为 `deny`，仅 `probe/src/capture.rs` 一处局部 allow（core-foundation
   0.10 缺一个带类型的 CFArray 项访问封装，两行 get-rule 转换；仅证据
   采集，不属链路）。正式 crate 迁移时不应带入此偏离。
