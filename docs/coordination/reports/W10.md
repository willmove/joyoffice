## 变更与边界

`plan_export` 的公开签名不变。成功计划的私有字段 `origin: Option<Arc<[u8]>>` 取自调用方 `PackageBacking` 里那份原始包字节的 `Arc` 克隆，不是重新导入时的拷贝，也不是后来写入 `bytes` 的补丁包。

```rust
impl ExportPlan {
    /// 与传入 `plan_export` 的 backing.original_bytes() 逐字节相同。
    /// 成功路径目前都是 Some。None 表示无法证明来源，save_original 必须拒绝。
    pub fn origin_bytes(&self) -> Option<&[u8]>;
}
```

不可伪造：字段私有，没有公共构造器或 setter。调用方只能把某个 `PackageBacking` 交给 `plan_export`，计划记录的就是这份 backing 的原始字节。文档版本相等不是同源证明。编辑后的 `bytes()` 会换成新包，`origin_bytes()` 仍是打开时的原包。把编辑结果重新导入再规划，新计划的来源是那份编辑后的包，不会继承更早的文件。

`PackageBacking` 增加了 crate 内方法 `original_arc() -> Arc<[u8]>`，用来共享分配、避免再拷贝整包。它不是公共 API，也不改变导入语义。任务卡写 backing.rs 仅文档与再导出；这里多了一个 crate 可见访问器，因为原始字节字段是私有的，不这样做就只能再复制一份，做不到 W07 提案里的廉价共享。公共导入行为没有变。

未改：importer、model、engine、OPC、shell 实现、app、Cargo、`save_original`。`save_original` 仍在写入前因 `OriginBindingUnproven` 等 blocker 拒绝。shell 测试只读 `origin_bytes()`，并确认即使来源字节与 `open_source` 读到的字节相同，`save_original` 仍然拒绝且不写临时文件。`save_export_copy` 仍只发布 `plan.bytes()`。

`ExportPlan` 没有 `Serialize`。克隆会再持有同一份 `Arc`（单元测试用 `Arc::ptr_eq`），克隆后 `origin_bytes`、输出字节、版本、模式和警告都保持相等。

规范来源：绑定的是 OPC 包原始字节（ECMA-376 Part 2 的包字节序列），比较是逐字节相等。这不是新的 WordprocessingML 标记条款，而是 W07 报告提案 1 与 `docs/coordination/wave03/INTERFACES.md` 的完整性要求。没有新依赖。

导出支持／拒绝矩阵没有变化：未编辑计划仍是 `OriginalPackage` 且警告为空；文字／W05 结构补丁仍是 `TextPatch`，仍带 `ZipMetadataRegenerated`，仍受原预算、限制、签名和未知标记拒绝。本任务没有做 W12 的带格式段落属性复制。
