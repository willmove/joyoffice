## 变更与边界

### 支持矩阵

结构编辑来自真实 engine 事务的快照，按身份对齐，不按文本相似度猜测源 XML：拆段时前段保留原身份和 SourceRef，后段是无来源的新身份；合并时保留第一段。

| 编辑 | 结果 |
| --- | --- |
| Enter 拆段：段首、段中、段尾；首段、中间段、末段；连续 Enter；多行粘贴 | 支持 |
| Backspace 或 Delete 在段落边界合并；跨多段选区删除；整段删除（RemoveBlock） | 支持 |
| 插入空段；新段中输入文字，含中文、emoji ZWJ、组合字符、首尾空白、tab、XML 特殊字符 | 支持 |
| 撤销／重做后的任意组合；重复导出 | 支持，输出确定，计划绑定当时版本 |
| 结构未变的段落中的文字修改 | 维持 C02 规则，可带格式，与结构编辑同时导出 |
| IME 组合态预览 | 不导出，只有提交后的事务才进入计划 |

“受影响段落”指：新段落、被删除的源段落，以及紧接着新段落、或其后有源段落被删除的存续源段落。它们必须满足以下全部条件：

- 段落样式为空，段落属性、段落标记属性和所有 run 的样式与属性都为默认值；
- 没有内联对象（含 w:br）；
- 只含 pPr、proofErr、r，run 内只含 rPr、lastRenderedPageBreak、t、tab；
- 段内没有任何保留片段，也没有注释或处理指令；
- w:p 的属性只在 W 或已知 Office 命名空间（rsid、w14:paraId／textId）；
- 不是节结束段（pPr 内无 sectPr）。

### 拒绝矩阵（ExportError::Unsupported 的原因字符串）

| 情形 | 原因 |
| --- | --- |
| 受影响源段落格式非默认（样式、jc、段落标记 rPr、粗体、未知 rPr 子元素、w:br 等） | paragraph structure edits require default paragraph and character properties |
| 新段落格式非默认（例如从带格式段落拆出的后段） | new paragraphs require default paragraph and character properties |
| 节结束段被拆分、合并或删除，或在其后插入新段 | paragraph ends a section |
| 受影响段落含注释或处理指令 | paragraph contains comments or processing instructions |
| 受影响段落含保留片段 | paragraph holds preserved markup |
| w:p 带未知命名空间属性 | paragraph has unknown attributes |
| 文本叶片带未知属性或命名空间 | 沿用 C02 的原因 |
| 段落移动或重复 | body structure or order changed |
| 新段落冒用原 SourceRef | new paragraph claims an original source |
| 新增非段落块；删除非段落块 | new non-paragraph block；non-paragraph block removed |
| 文本含 XML 1.0 无法表示的字符（U+FFFE、U+FFFF、C0 控制符），新段落与原有文字修改路径都适用 | text contains … XML cannot represent |

受限、锁定、签名、模板或宏文档仍分别返回 Restricted、SignedPackage、Unsupported，与 C02 一致。超出原预算时返回 Budget，重新导入超出 XML 节点预算时返回 Import。拒绝不改 backing 和会话版本，旧计划保持不可变。

### 写出方式

- 被删除的源段落：只删除其元素的字节范围。新段落：写在当前顺序中前一个存续源块之后；若前面没有存续源块，写在源 body 首块之前；连续新段落一次写入。其余字节、其他部件、内容类型与关系保持不变。
- 新段落与“空段写入文字”路径使用 w:body 处作用域内已绑定 W 的前缀：优先 w，其次其他前缀，再次默认命名空间；都不可用时才退回自声明的 jwe 前缀。输出形如 `<w:p/>`、`<w:p><w:r><w:t xml:space="preserve">…</w:t></w:r></w:p>`，tab 为 `<w:tab/>`。新段落不复制源段落的 w14:paraId、rsid、pPr 或 sectPr。
- 原有文本叶片的替换仍是 C02 的 `jwe:t` 字节，未改。空段写入文字的 run 从 `jwe:r` 改为作用域前缀：macOS textutil 不识别 `jwe:p`／`jwe:r`，会丢掉该元素及其后全部内容（实测见下文）。
- 写出后用同一预算重新导入，并检查四项：文档无限制；语义等价；节边界在相同段落位置；全部保留片段按部件、元素、命名空间上下文和字节构成的多重集合一致。语义等价的判定先把保留句柄按其片段内容规范化，再合并同格式 run 后比较 canonical dump。规范化是必要的，因为保留句柄与节点 ID 共用计数器，新增或删除段落会使后续句柄编号整体偏移；而 dump 只写 `last=block`，不说明哪一段结束节。后三项也适用于原有文字修改路径，只会更早拒绝，不会放宽。
