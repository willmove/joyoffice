本切片映射到模型的内容：

- 包与主文档：经 OPC 层读取，复用其全部预算、严格 ZIP、部件名和关系检查。主文档按包关系 officeDocument 定位，不按路径猜测。主文档内容类型限于 document、template 及两种启用宏的变体。以下情况拒绝：关系缺失、重复、指向外部或悬空；Strict 关系类型或命名空间（报 `StrictUnsupported`）；根元素不是 `w:document` 加 `w:body`。
- 正文：逐个顶层块流式读取，不建立整个 document.xml 的树。
  - `w:p` 映射为 Paragraph，`w:sectPr` 映射为节，其余顶层块（表格、内容控件、未知元素等）成为 OpaqueBlock。
  - 段内映射 `w:t` 的文字，以及 `w:tab`（`\t`）、`w:br`（无类型或 textWrapping、page、column，且 clear 为 none）和 `w:cr`。
  - `w:t` 的文字逐码点保留，有没有 `xml:space` 都一样，见下文“空白”。
- 属性：只取基础子集，并保持源单位。
  - 段落：pStyle、jc、ind（含 *Chars）、spacing（含 *Lines 和 auto 间距）、keepNext、keepLines、widowControl、pageBreakBefore、snapToGrid、outlineLvl、numPr，以及段落标记的 rPr。
  - 字符：rStyle、b、i、strike、vanish、u、sz、rFonts 四槽与 theme 及 hint、color、lang。
  - 未设置是 None，显式关闭是 Some(false)。
- 样式：映射 docDefaults 和 `w:style`（type、styleId、name、basedOn、next、link、default、customStyle，以及 pPr/rPr 子集）。
  - 省略 type 时按段落样式处理。内置样式由模型按 `w:name` 规范名识别，测试覆盖中文 ID `a`、`1`、`a0`，不按 styleId 猜测。
  - 重复的 styleId 保留第一个，其余进入 backing 并给出诊断。
- 节：映射 pgSz（w、h、orient）、pgMar 的 7 个边距和 titlePg。段内 `pPr/sectPr` 形成节边界。缺少的值用产品默认 A4 补齐，并报告 SectionDefaults。
- 设置：
  - 兼容模式只读取 uri 为 `http://schemas.microsoft.com/office/word` 的 compatSetting。原值保留；缺失时保持 None，由模型按 12 解释。导入路径从不写入 15。
  - 另外读取 trackRevisions、evenAndOddHeaders、documentProtection 和 writeProtection。

保留边界。下列内容都保留，不静默丢弃：

- PackageBacking 保存原文件全部字节，供未编辑时原样写回，以及 OPC Package（每个部件的精确解压字节、内容类型、关系和 `[Content_Types].xml` 原文）。
- 模型无法解释的元素登记为 Fragment，记录部件内字节范围和外层命名空间上下文，模型通过 PreservedId 引用它：
  - 块级元素成为 OpaqueBlock，行内元素成为 `InlineKind::Preserved`。
  - 超链接、smartTag、customXml、fldSimple、dir/bdo、ins/moveTo 这类包装元素：进入其中读取文字，包装本身保留。
  - 书签、批注范围、权限范围这类区间标记：保留，但不占文本位置。
  - 属性元素中有模型没有字段的子元素时，整个元素保留，并设置 `props.preserved`、`style.preserved`、`section.preserved`、`settings.preserved`。
- 段落里的模型对象带 SourceRef（部件名加 `@start..end` 字节范围）。
- `w:proofErr` 和 `w:lastRenderedPageBreak` 不进入模型，按部件汇总计数后报告 HintsSkipped，原字节仍在部件里。

可编辑边界：

- 含保留内容的段落或块进入 `locked`，`can_edit` 返回 false。只在属性中保留内容的，不锁定文字编辑。
- 以下情况使整篇文档只读：
  - 强制的文档保护。缺少 enforcement 时按 Word 的行为视为强制，见 [MS-OI29500]。
  - writeProtection。
  - trackRevisions。
  - 正文出现修订标记；预扫描范围包括被保留的子树。
  - `mc:MustUnderstand` 列出了未理解的命名空间。
  - 出现既不在 W 命名空间、不是已知 Office 命名空间、也不可忽略的元素。
  - 模型校验失败。
- 未知或受保护的输入一律有诊断，不会返回“无诊断的可编辑结果”。
- 本 crate 没有任何编辑后保存路径，`original_bytes()` 的文档写明只适用于未编辑的文档。

外部链接：遍历所有关系，对外部目标只记录并分类（网页、文件、网络共享、邮件、其他），从不解析或访问。网络共享和本地文件报 Warning，网页和邮件报 Info。

XML 安全：新增的 XML 读取器与 OPC 层规则一致：

- 拒绝 DOCTYPE，因此不会有 DTD 或内部、外部实体。
- 只展开 5 个预定义实体和合法的字符引用，其他实体报错；非法 XML 字符引用报错。
- 拒绝 UTF-16，以及声明为非 UTF-8 的编码。
- 未声明的前缀、重复属性、标签不匹配、未闭合或截断都报错。
- 读取过程中按 `Budget.max_xml_depth`、`max_xml_nodes` 计数，在完成对应工作之前就会失败。
- 诊断最多保留 1024 条，超出的只计数；只读原因单独保存，不会被截断。

支持范围之外（未覆盖）：保存和导出、ExportPlan、原子替换、表格、内容控件、页眉页脚和脚注/尾注/批注 story、编号定义、书签和域映射为 annotation、图片和绘图、`mc:AlternateContent` 的分支选择、Strict、跨样式层级的属性解析、universal measure（如 `2cm`）。universal measure 目前报 InvalidValue，并保留所在元素。

需要协调者知晓的语义选择：

1. 空白。§17.3.3.31 把没有 `xml:space="preserve"` 时的首尾空白交给 XML 1.0 §2.10，即由应用决定。本实现逐码点保留，并对这种情况报 Info `UnpreservedWhitespace`。Word/WPS 是否显示这些空白，需要 T004 参考结果确认。
2. 同时写了 *Chars/*Lines 与绝对值时：非零的相对值优先，值为零时取绝对值，与 [MS-OI29500] 一致。整个元素会被保留，因此两种值都不会丢。跨样式层级的解析留给排版。
3. documentProtection 省略 enforcement 时按强制处理。规范认为不强制，Word 实际会强制，这里取更保守的读法。

## 接口或依赖提案

1. engine 的节点级锁定（建议，未实现）。`EditPolicy` 现在只有整篇文档的 `read_only`。`Editability::locked()` 给出的节点，目前只有调用方能自己拒绝。建议在 engine 中以增量方式增加 `EditPolicy.locked: BTreeSet<NodeId>`（或谓词），让 Transaction 在定位到锁定段落或块时返回 `TxError::Locked`。在此之前，接入方可以用 `editability.is_read_only() || !editability.locked().is_empty()` 映射到 `read_only: true`，这是最保守的接法。
2. 模型的超链接和书签映射（下一轮）。AnnotationKind 已有 Bookmark、Field、Permission，可以把书签和域映射为 annotation，从而解除大量 `_GoBack` 书签造成的段落锁定。超链接目前没有对应的模型类型，需要协调者决定在 AnnotationKind 增加 Hyperlink，还是作为行内对象。
3. 依赖：无新增。
