### 与代码事实不一致时以代码为准

- 实验 `Recovery::validate` 只接受默认属性的纯文本正文（无样式、无 pPr／rPr、无内联、单 story）。main 上的导出已经能处理 W05 默认格式结构编辑和 W12 完全映射的 pPr／rPr。实验日志**不能**表示这些格式。不能把 W12 文档塞进 schema 1 再声称恢复成功。
- `DocumentVersion` 单调递增。撤销和重做发布新版本，不复用旧版本号（`joyword-model` 的类型注释，以及 ARCHITECTURE §4）。
- 两套“未保存”不要混用。`OpenDocument::is_dirty` 是 `session.version() != saved`。`TextInput::has_unsaved_changes` 是 `version() != initial_version`（导入版本）。撤回到导入时的文字后，版本已经前进，后者仍为真。恢复日志的 dirty 对齐 `OpenDocument`：已成功记入的保存版本与当前版本不同才算 dirty。关闭提示仍沿用 C07，不因为日志 dirty 为假就跳过那次确认。
- `save_export_copy` 不改来源、不改 backing、不改撤销栈、不清 dirty（`storage` 模块注释与 C03）。C09-B 禁止把副本成功显示成原件已保存。
- 实验用段落序号加 Unicode 标量定位，不持久化 `NodeId`。重新导入后的节点号与旧进程不一致。这个约束保留。
- 组合预编辑没有日志 API。只有 engine 已提交的事务可以记入。

### 会话生命周期

日志目录与文档锁分开，不放在 DOCX 旁边，以免被当成 Word 的 `~$` 或 JoyWord 的 `.<文件名>.joyword-lock`。目录由应用私有恢复根持有，键是会话 id。记录内部保存源路径、源包 SHA-256 和打开时的包字节。路径改名不作为唯一身份。

1. 打开。`open_source` 成功后才允许 `DocxSession::open`。失败不安装会话，也不创建日志。此时还不自动重放。
2. 若该源没有未完成日志：仅当文档落在可恢复子集内，才写入 kind 1 基线（源哈希加原始包字节），`write_all`、`flush`、`sync_all` 都成功之后，会话才标成可恢复。子集外的文档照常编辑，界面说明崩溃恢复不可用。
3. 若已有日志：先 `scan` 出连续有效前缀，再按下面的选择界面让用户决定。在用户选择前不追加、不删除、不覆盖源文件。
4. 编辑。engine 事务成功并发布新版本之后，把该事务编码成一条事件并同步追加。顺序以活会话为准：日志失败不回滚已经显示的编辑，而是把日志标成 poisoned，停止后续追加。这与实验 `commit` 先落盘再发布候选不同；实验可以那样做，是因为它自己握着唯一会话。生产会话的撤销栈已经在 engine 里，不能为了日志再做一次撤销。
5. 撤销／重做。各记一条只含 `Undo` 或 `Redo` 的事件，由 engine 执行。不另建撤销栈（ADR-004）。
6. 关闭且用户取消。日志保持原样，会话保持原样。
7. 关闭且用户丢弃。先关掉会话，再归档或删除日志。崩溃发生在这两步之间时，下次启动仍给出恢复选择，用户可以再丢弃。不删除源 DOCX。
8. 关闭且要保存。只有当前版本的 `save_original` 回执被接受、并且 `Saved` 记录也同步成功、且当前版本等于该保存版本时，日志才可以退役。副本路径不能代替这一步。
9. 进程消失。不依赖析构函数删日志。下次启动从有效前缀恢复。

检查点仍由调用方触发，不建后台服务。两代轮转沿用实验：新的一代先 `create_new` 成 pending，写完、同步、逐字节读回并真实重放之后，才替换老一代。另一代和源日志在替换过程中都保留。中断留下的 pending 不自动删除。源日志、两代和一份 pending 各自不超过 32 MiB。唯一恢复链在新检查点持久化完成前不删除。

### 落盘时机

| 事件 | 何时同步 | 失败时 |
| --- | --- | --- |
| 基线 | 会话标成可恢复之前 | 会话可以编辑，但不可恢复 |
| 已提交事务 | 版本发布之后、下一次依赖恢复的动作之前 | poisoned，停止追加 |
| `Saved` 回执 | `save_original` 回执已证明文件写完，且会话仍是发出请求的那一个 | 文件保持已保存；内存里的 saved 版本按回执更新；日志若没写上，下次启动必须用字节比较，不能用版本号覆盖较新的文件 |
| 检查点 | 调用方在事件或字节阈值处显式调用 | 旧一代仍可恢复；pending 留下 |
| 预编辑、布局、导出计划生成 | 不写日志 | |

实验上限保持为上限，产品只能收紧：单记录 8 MiB，单文件 32 MiB，4096 条记录，单事件最多 128 个动作，事件正文 4 MiB。CRC-32 只发现损坏，不证明没有被改写。SHA-256 用来核对基线和事件前后的正文指纹。

`Saved` 的版本必须 `<=` 当前版本且 `>=` 上一次保存版本，与实验 `Action::Saved` 的检查相同。迟到回执在会话已关闭后丢弃，不重建会话。保存过程中用户又编辑时，回执只推进 saved 版本，dirty 仍为真。

### 与保存 API 的关系

`plan_export` 的 `origin_bytes()` 是打开时的包字节（W10：`origin: Some(backing.original_arc())`）。日志基线哈希必须等于这份字节的 SHA-256。版本相等不能代替这个比较。

- `save_export_copy` 发布的是某一版 `plan.bytes()` 的新路径。它不是日志基线，不写 `Saved`，不改 `OpenDocument` 的 saved 版本，不改 origin。之后继续编辑仍记在原来的链上。以后打开那个副本是一次新的 `open_source`，基线是副本自己的字节。
- `save_original` 在 W11 于某个平台真正去掉 blocker 之前，恢复设计不假设它会成功。成功之后，磁盘文件代表回执上的版本；日志仍从打开时的基线重放，而不是把新文件当成可以丢链的唯一真相。启动时要重建出该保存版本对应的文本，再和磁盘字节比较。对不上就隔离，不覆盖。
- 恢复副本使用 `save_export_copy` 或实验里那种 `create_new` 的新路径。两条路都不覆盖已存在目标。恢复出来的会话 dirty 为真，直到用户对这个新文件做了一次被接受的原件保存。不能把“已从日志恢复”显示成“原件已保存”。

### 崩溃恢复选择

启动时若有效前缀比磁盘文件新，或尾部被截断，先显示选择，不自动应用。

```text
发现未保存的恢复记录
文件：<源文件名>
会话：<16 字节会话 id 的十六进制>
有效前缀：<字节数>，记录 <n> 条
尾部：完整 / 已截断（不重放尾部）
恢复到版本：v<after>    已记录的保存版本：v<saved>
未保存：是 / 否
预览（有界，只读）：<最后完整事务的正文前若干字>

[打开为新副本]    默认。新路径，不覆盖源文件。
[打开磁盘上的文件]  不重放。日志保留，稍后仍可再选。
[丢弃恢复记录并打开磁盘文件]  需要再确认一次。不删除源文件。
```

下列情况不提供“写回源文件”：

- 源哈希或当前文件字节与日志基线、任一已重建版本都不一致。
- 文档含日志不能表示的格式或对象。此时只说明“这份日志不能安全重放”，并打开磁盘文件或保留日志供诊断。
- 日志 schema 不是已知版本。整份拒绝，不改源文件。

界面不出现“保存成功”。取消关闭了选择框时，不删除日志。

### 与 W11 文件锁的职责

| | 文档锁（W07 检测，C09 创建／释放，W11 只检测） | 恢复日志（本设计，尚未实现） |
| --- | --- | --- |
| 位置 | 与 DOCX 同目录：`~$…`、`.<文件名>.joyword-lock` | 应用私有目录中的会话日志 |
| 含义 | 可能有人正打开这个文件 | 这个进程有一条未退役的编辑链 |
| 谁写入 | Office 写 `~$`。JoyWord 锁的创建和释放归 C09 会话生命周期。W11 不创建、不删除 Office 锁 | 只有持有该会话的进程追加。实验没有跨进程锁 |
| 对 `save_original` 的影响 | 锁还在则 W11 在写入前拒绝 | 日志代码不调用 `save_original`，也不变成 storage 的后端 |
| 第二进程 | 看到锁就不要再追加同一条日志 | 独占目录是前提。不保证恶意目录竞争 |

恢复检查可以只读扫描日志。生成新副本不需要取得源文件的替换权。丢弃日志不释放 Office 锁，也不删除 `~$`。

### 平台验证缺口

W08 的实测环境是 macOS 27.0.1、APFS，用父进程 `SIGKILL` 子进程。那不是断电，也不是 Windows。交叉编译 `x86_64-pc-windows-msvc` 只说明能检查，不能代替原生运行。本设计在 Linux 上写文档，没有补跑实验，没有 NTFS 证据。

仍未验证、以后实现也不能凭本文件勾掉的项目：

- Windows 原生 MSVC：创建文件、`sync_all`、rename 替换、共享冲突、杀进程后的有效前缀。
- NTFS 与 Unix 的目录项持久化不一样。实验里 Unix 才记录 `directory_synced`。Windows 上不能把文件 `sync_all` 说成检查点目录已落盘。
- 断电、休眠中断、远程文件系统、杀毒软件锁文件。
- Linux 上实验测试此前没有作为 W08 的验收主机。现有 CI 不运行 `experiments/recovery-journal`。CI 绿色只说明本 Markdown 没有把文档检查跑坏。
