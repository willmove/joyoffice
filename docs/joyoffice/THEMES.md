# JoyOffice 界面主题

2026-11-11。JoyWord、JoyDeck 和 JoySheet 共用四种风格、八个预设。主题只改变应用界面，文档页面、幻灯片及单元格中的实际颜色继续由文档控制，保存和导出不因界面主题改变。

## 现有风格分析与命名

| 风格 | 来源与特征 | 默认使用方 | 预设 ID |
| --- | --- | --- | --- |
| 青岚 / Verdant | 原共享 Palette：浅青灰底、白色面板；暗色为深青绿。Word 的蓝色与 Sheet 的绿色是产品强调色，底色、字色、边框、间距及圆角相同，因此归为同一风格 | Word、Sheet | `verdant-light`、`verdant-dark` |
| 素雅 / Classic | 原 Deck chrome：中性灰底、白色面板、深灰文字；暗色为石墨灰。Deck 沿用橙色强调；亮色文件页的灰蓝导航色纳入 header 色 | Deck | `classic-light`、`classic-dark` |
| 晴空 / Azure | 新增冷蓝灰底与蓝色强调，暗色为深海军蓝；三个产品使用相同配色 | 可选 | `azure-light`、`azure-dark` |
| 暖砂 / Sandstone | 新增米白、砂色面板与棕色强调，暗色为深棕与暖金；三个产品使用相同配色 | 可选 | `sandstone-light`、`sandstone-dark` |

青岚和素雅均保留产品强调色。素雅暗色的 Deck 强调色调整为浅橙，以满足小字号标签和按钮文字的对比度。应用尺寸与布局继续遵循各产品现有界面，不把 Ribbon 布局差异误当成另一个颜色主题。

## 使用与兼容

- Word：文件 → 选项 → 界面主题。
- Deck：文件 → 选项 → 外观。
- Sheet：标题栏「设置」→ 界面主题。
- 八个预设均提供名称、配色缩略预览、辅助功能选中状态及键盘激活处理。标题栏原有明暗按钮只切换当前风格的亮暗版本。完整原生键盘遍历仍需补验。
- 每个产品独立保存偏好。Word 在原 `migration-preview/preferences.conf` 增加 `appearance.theme`，继续写入旧 `preview.theme`；没有新键时保留原亮暗选择和其他未知配置。
- Sheet 在原 `preferences.json` 增加 `theme`，同步旧 `dark`；旧配置和未知预设回退到原青岚亮暗风格，保留语言、最近文件等其他偏好。`ui.set` 支持预设 ID，拒绝无效主题或冲突的 `theme` / `dark`，不提交部分修改；`ui.inspect` 返回当前主题和可用 ID。
- Deck 在现有 `recovery_root()` 下的 `appearance.v1` 保存预设 ID，与最近文件索引相邻。读取上限 128 字节，使用已有原子保存和冲突检测。首次启动使用素雅亮色；`--dark` / `--light` 覆盖本次模式，`--theme=PRESET` 可覆盖本次预设，只有用户在界面选择后才保存。
- 保存失败时保留当前外观并显示错误。同一应用内的其他编辑窗口跟随完整预设变化。

## 实现边界

`joyoffice-theme` 是无 GUI、无文件访问、无外部依赖的公共主题目录，提供稳定 ID、默认主题、亮暗配对和 Palette。`joyoffice-ui` 保留既有 Palette API 的再导出，并负责预览及 GPUI Kit 投影；按钮、输入框、菜单、弹窗和 Base tokens 随主题一起刷新。主题偏好仍由各产品已有存储边界负责，不向文档模型引入界面主题。

Sheet 的行列标题、滚动条和选择标记采用主题色；工作表单元格继续显示文档原色。纸面上的选框使用该风格亮色版本的强调色，避免暗色界面的浅色强调在线框与白纸之间失去对比度。

## 验证

新增测试覆盖八个预设 × 三个产品的文字／控件对比度、旧配置兼容、主题持久化及保存失败回滚。macOS ARM64 已实窗验证三个产品的设置页、亮暗切换、重启恢复及 Deck 新窗口继承；Sheet 原生控制专项覆盖全部八个预设、无效参数拒绝、文档修订保持和两个原生窗口间的完整预设同步。具体运行结果、截图及现有回归限制见[本次验证记录](validation/20261111-themes/README.md)。Windows／Linux 原生、完整键盘遍历、读屏和全部 DPI 组合尚未验收。
